    3. Comunicacions i programació multifil

    Comunicacions i programació multifil

    Com ja hem avançat, la forma d'implementa la part servidor en la comunicació d'aplicacions és mitjançant la programació multifil, ja que han de ser capaços de processar diverses peticions de manera simultània.

    Necessitat de la programació multifil en les comunicacions

    Veurem un xicotet exemple sobre per què necessitem utilitzar programació multifil per a processar diverses peticions. Per a això, en l'exemple de tire anterior, afegirem una xicoteta modificació.

    Modifiquem el següent codi en la implementació del servidor:

    public void listen() throws IOException{
        [...]
        while (true){
                [...]
            }
            [...]
            pw.write(resposta+"\n");
            pw.flush();
            pw.close();
            os.close();
    }

    Per:

    public void listen() throws IOException{
        [...]
        while (true){
                [...]
            }
            [...]
            pw.write(resposta+"\n");
            pw.flush();

            // Pausa abans de tancar la connexió
            try{
                System.out.println("Esperant 10 segons...");
                Thread.sleep(10000);
            } catch (InterruptedException ie){
                System.out.println("S'ha inerromput la pausa...");
            };

            pw.close();
            os.close();

    }

    Amb aquest canvi, l'única cosa que fem és afegir una pausa al fil d'execució principal de 10 segons abans de tancar la connexió. Si executem en un parell de terminals dos clients:

    Terminal 1(Servidor) Terminal 2 (Client 1) Terminal 3 (Client 2)
    $ java ecoServer
    > Iniciant el servidor...
    $ java ecoClient 127.0.0.1 "Hola don Pepito"
    Connexió a: Socket [addr=/127.0.0.1, port=9999, localport=38930]

    S'ha rebut la connexió
    <log> Received... Hola don Pepito
    Hola don José
    Esperant 10 segons...
    $ java ecoClient 127.0.0.1 "Pasó usted por mi casa?"
    Connexió a: Socket [addr=/127.0.0.1, port=9999, localport=39142]
    Espera bloquejant...

    S'ha rebut la connexió
    <log> Received... Pasó usted por mi casa?
    Por su casa yo pasé
    Esperant 10 segons...
    Espera bloquejant...

    Com veiem, la pausa que hem afegit després d'enviar una resposta ha fet que es tardara a atendre la segona petició realitzada sobre el servidor. Aquesta pausa ha sigut intencionada, però penseu en servidors que reben moltes peticions: encara que els servidors tarden poc a atendre les peticions, a mesura que arriben més peticions, els retards van acumulant-se, ja que se serveixen una a una, fent que si es connecten molts clients, el temps d'espera siga inassumible per a aquests.

    Així doncs com hem comentat, quan una aplicació necessita acceptar diverses connexions, caldrà fer ús d'una classe de tipus Thread o que implementa la interfície Runnable que ja coneixem, de manera que per cada connexió llancem un fil.

    Així doncs, modificarem el codi del nostre servidor de ressò perquè siga multifil.

    Implementació d'un servidor de ressò multifil

    Per a realitzar el nostre servidor multifil, necessitarem una classe que genere les respostes i que implemente Runnable. Aquesta nova classe, la cridarem generadorEco, i tindrà el següent aspecte:

    class generadorEco implements Runnable{
    private Socket MySocket;

    generadorEco(Socket socket){
        MySocket=socket;
    }

    @Override
    public void run() {
        try{
            // Aci implementarem tot el codi 
            // per generar una resposta en funció 
            // del missatge rebut a través del socket.
            // (El codi serà idèntic al que feia aquesta
            // functionalitat al servidor d'eco monofil)
    }

}

    i la classe que implemente el servidor, que anomenarem multiEcoServer, tindrà el següent aspecte:

    public class multiEcoServer {

    public void listen() throws IOException{
        System.out.println("Iniciant el servidor...");

        ServerSocket listener=null;
        int srvPort=9999;
        try {
            listener=new ServerSocket(srvPort);
        } catch (IOException e) {
            System.out.println("El port "+srvPort+" està ocupato és inaccessible.");
            return;
        }

        // Iniciem un bucle infinit a l'espera de rebre connexions
        while (true){
            Socket socket=listener.accept();

            // L'ordre anterior és bloquejant, quan arriba aci, ha rebut una connexio
            System.out.println("S'ha rebut la connexió. Generant resposta.");

            // Creem un objecte de tipus generadorEco i el llancem en un thread
            generadorEco generador=new generadorEco(socket);
            Thread generadorThread=new Thread(generador);
            generadorThread.start();

        }
    }

    public static void main(String[] args) throws IOException {

        multiEcoServer es=new multiEcoServer();
        es.listen();

    }

}

    Com veiem, la principal novetat es troba en les línies;

    // Creem un objecte de tipus generadorEco i el llancem en un thread
generadorEco generador=new generadorEco(socket);
Thread generadorThread=new Thread(generador);
generadorThread.start();

    Que ens creen un objecte nou, de tipus generadorEco, al qual li passem el socket pel qual es comunicarà amb el client; aquest objecte el convertirem en fil, i executarem (mitjançant start) el seu mètode run que s'encarregarà de realitzar aquesta comunicació.
