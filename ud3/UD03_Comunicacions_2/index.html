    2. Biblioteques per a programar aplicacions en xarxa. Sockets

    Llibreries per a la programació d'aplicacions en xarxa. Sockets

    La biblioteca Java per a la programació d'aplicacions en xarxa és java.net.

    Un xicotet exemple introductori: La classe URL

    Com un primer exemple a l'API de java.net, veurem la classe URL, que permet gestionar accessos a adreces web, i descarregar fitxers de manera senzilla.

    El següent exemple, la classe DownloadMan, serà un gestor de descàrregues que exemplifiquen l'ús de les classes URL i URLConnection per a descarregar fitxers des d'una URL

    Fixeu-vos en què la lectura dels recursos a través de la xarxa es realitza també mitjançant streams, tal com si foren fitxers locals. A més, en l'exemple, distingirem si es tracta d'un fitxer de tipus text o no, per a utilitzar un objecte InputStreamReader per a la lectura o directament el InputStream. Aquesta distinció la fem per a exemplificar com es faria en l'un o l'altre cas, però en la pràctica, podríem utilitzar el InputStream de manera genèrica per a tota mena de fitxer i simplificar el codi.

    import java.io.FileWriter;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.BufferedReader;

import java.io.FileOutputStream;

import java.net.*;

public class DownloadMan {
    public void download(String url, String filename){
        try {
            URL myURL = URI.create(url).toURL();

            // Determinem el tipus de fitxer
            URLConnection uc = myURL.openConnection();
            String type = (uc.getContentType().split("/"))[0];
            System.out.println("type:"+type);

            // Obrim el flux:
            InputStream is=myURL.openStream();

            if (type.equals("text")){
                // Descarreguem el fitxer com a text
                System.out.println(url+" és un text. Descarregant... ");

                InputStreamReader reader=new InputStreamReader(is);
                BufferedReader bReader=new BufferedReader(reader);
                FileWriter fWriter=new FileWriter(filename);
                String line;
                while ((line=bReader.readLine())!=null){
                    fWriter.write(line);
                }
                fWriter.close();
                bReader.close();
                reader.close();

            } else {
                // Si no és un text, descarreguem el fitxer com a stream
                System.out.println(url+" és un fitxer. Descarregant... ");

                int bytes, bytesCopied=0;
                FileOutputStream fout=new FileOutputStream(filename);
                do {
                    bytes=is.read();
                    // Escrivim el byte al fitxer d'eixida
                    if (bytes!=-1) fout.write(bytes);
                    System.out.println("Llegits.. " + bytesCopied);
                    // Actualitzem el nº de bytes copiats
                    bytesCopied++;
                }while (bytes!=-1);
                System.out.println("Descarregats "+bytesCopied+ "bytes");
                fout.close();
            }
            // Tanquem l'stream de lectura
            is.close();
        } catch (MalformedURLException e) {
            System.out.println("Excepció: URL mal formatada!");
            return ;
        } catch (IOException e) {
            System.out.println("Excepció no controlada: "+e.toString());
            return ;
        }
    }

    public static void main (String[] arguments){
        DownloadMan dMan=new DownloadMan();

        if (arguments.length!=2) 
            System.out.println("Sintaxi incorrecta. Heu d'indicar una URL i un nom de fitxer");
        else{
            // Exemles d'urls:
            //String url="http://joamuran.net/docencia/psp";
            //String url2="http://joamuran.net/docencia/psp/u1/img/estats.png";
            dMan.download(arguments[0], arguments[1]);
        }

    }
}

    Fixeu-vos també que els constructors de URL estan obsolets des de Java 20. Per això l'exemple crea primer un URI i el converteix amb toURL(). URI.create() llança IllegalArgumentException si la sintaxi no és vàlida, mentre que toURL() pot llançar MalformedURLException si no es pot fer la conversió.

    Com veiem, la classe URL ens ofereix el mètode openStream, que ens retorna un InputStream amb el flux de bytes del fitxer. A més, amb el mètode getContentType de la classe URLConnection, podem saber de quin tipus és el fitxer, i d'aquesta manera llegir-lo com a línies de text o com a bytes.

    Aquestes classes ens proporcionen un mecanisme senzill però lligat al protocol de les URL. Si volem tindre un major control sobre les dades que rebem i enviem, i una major versatilitat, hem de recórrer als sockets.

    Per a clients HTTP nous, Java 11 i posteriors ofereixen java.net.http.HttpClient, amb suport d'HTTP/2 i operacions síncrones o asíncrones. URLConnection continua sent útil per a explicar els fluxos, però no és l'opció preferida per a construir un client HTTP actual:

    HttpClient client = HttpClient.newHttpClient();
HttpRequest peticio = HttpRequest.newBuilder(URI.create(url)).GET().build();
HttpResponse<Path> resposta = client.send(
    peticio,
    HttpResponse.BodyHandlers.ofFile(Path.of(filename))
);
System.out.println("Estat HTTP: " + resposta.statusCode());

    Programació amb Sockets

    Un socket és un concepte abstracte que permet a dos programes (possiblement en ordinadors diferents) intercanviar fluxos de dades, generalment de manera fiable i ordenada. Els sockets es defineixen per una adreça de socket, formada per una adreça IP, un protocol de transport (TCP/UDP) i un número de port.

    A nivell d'implementació en Java, els sockets són objectes que permeten comunicar programes i servidors remots. Aquests objectes ens proporcionaran fluxos d'entrada i/o eixida per a poder comunicar aquests processos.

    Un altre tipus de sockets en Java són els ServerSockets, que s'utilitzen per a crear programes que accepten connexions o peticions. A mesura que anem avançant la unitat veurem la diferència entre ambdos.

    Com hem comentat, totes dues classes es troben en la llibreria que gestiona les comunicacions en xarxa java.net

    Creació de sockets

    Quan hem parlat sobre la pila TCP/IP, hem comentat que per a comunicar dues aplicacions necessitem una connexió punt a punt entre aquestes. Aquests punts es componien d'una adreça IP o un nom DNS (que es traduirà en una IP), i un número de port, TCP o UDP. Doncs bé, aquesta és la informació que necessitarem per a crear un socket.

    Vegem-ho amb un exemple:

    import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.*;
import java.io.IOException;

public class Connect {
    public static void main(String[] args) {

        if (args.length!=2) {
            System.out.println("Has d'indicar una adreça web i un port");
            System.exit(-1);
        }

        String dst=args[0];
        int portDst=Integer.parseInt(args[1]);

        Socket socket=new Socket();
        InetSocketAddress socketAddr=new InetSocketAddress(dst, portDst);

        try {
            socket.connect(socketAddr);
            // Connexió realitzada amb èxit
            System.out.println("S'ha realitzat la connexió exitosament a "+socketAddr.toString()+". Ara procedirem a tancar-la.");
            // Tancament d ela connexió
            socket.close();
        } catch (IOException e) {
            System.out.println("Excepció en la connexió: "+e.getMessage());
        }  
    }
}

    El codi és bastant senzill d'interpretar. Capturem dos arguments des de la línia d'ordres, una URL (o IP) i un port, i amb aquests creem un objecte de tipus InetSocketAddress:

    InetSocketAddress socketAddr=new InetSocketAddress(dst, portDst);

    Abans d'això, hem creat un objecte de tipus Socket:

    Socket socket=new Socket();

    Amb ambdos objectes de tipus socket (Socket) i Adreça d'Internet (InetSocketAddress), realitzarem la connexió de la següent forma:

    socket.connect(socketAddr);

    Si l'ordre connect no llança cap excepció, aquesta s'haurà realitzat de manera reeixida, per la qual cosa ja podem utilitzar el socket per a comunicar-nos amb l'altre extrem. Finalment, si la connexió s'ha realitzat (i després d'haver realitzat les operacions pertinents), la tancarem amb:

    socket.close();

    L'ordre connect pot llançar una excepció de tipus IOException, que pot significar que:

    • La connexió no s'ha pogut realitzar, o bé que
    • A pesar que la connexió s'ha establit, no s'han pogut llegir o escriure dades

    Amb el mètode getMessage de l'excepció, podrem consultar quin ha sigut l'error concret

    Vegem alguns exemples de funcionament:

    • Connexió a un port ben definit d'una adreça DNS d'Internet:
    $ java Connect www.google.com 443
Se ha realizado la conexión exitosamente a www.google.com/216.58.201.132:443. Ahora procederemos a cerrarla.
    • Connexió a un port ben definit d'una adreça IP:
    $ java Connect 127.0.0.1 80
Se ha realizado la conexión exitosamente a /127.0.0.1:80. Ahora procederemos a cerrarla.
    • Connexió a un port no definit en una adreça IP:
    $ java Connect 127.0.0.1 81
Excepción en la conexión: Se ha rehusado la conexión (Connection refused)

    Ús de sockets per a enviar i rebre informació

    La classe Socket ens ofereix els mètodes getInputStream i getOutputStream que ens ofereixen fluxos orientats a bytes per a llegir i escriure de l'i al socket, respectivament.

    Modificarem l'exemple anterior per a llegir el contingut d'un document indicat per la línia d'ordres, de la següent manera:

    $ java ConnectAndShow moodle.ieseljust.com 80 ""

    java ConnectAndShow www.google.es 80 ""

    El codi complet seria:

    import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.*;
import java.io.IOException;

import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.BufferedReader;
import java.io.PrintWriter;

public class ConnectAndShow {
    public static void main(String[] args) {

        if (args.length!=3) {
            System.out.println("Has d'indicar una adreça web, un port i un recurs");
            System.exit(-1);
        }

        String dst=args[0];
        int portDst=Integer.parseInt(args[1]);

        Socket socket=new Socket();
        InetSocketAddress socketAddr=new InetSocketAddress(dst, portDst);

        try {
            socket.connect(socketAddr);
            // Connexió realitzada amb èxit
            System.out.println("S'ha realitzat la connexió exitosament a "+socketAddr.toString()+". Ara procedirem a tancar-la.");

            // Obtenció dels streams d'entrada i eixida
            InputStream is=socket.getInputStream();
            OutputStream os=socket.getOutputStream();


            // Creem fluxos per a la lectura i escriptura de caràcters
            InputStreamReader isr=new InputStreamReader(is);
            OutputStreamWriter osw=new OutputStreamWriter(os);

            // Creem fluxos per a la lectura i escriptura de línies
            BufferedReader bReader=new BufferedReader(isr);
            PrintWriter pWriter=new PrintWriter(osw);

            // Escrivim al socket l'ordre GET del protocol HTTP per obtenir el document demanat
            String command="GET /"+args[2]+ "\r\n\r\n";
            System.out.println("HTTP Request: "+command);
            pWriter.println(command);
            pWriter.flush();


            String linia;
            while ((linia=bReader.readLine()) != null ){
                System.out.println(linia);
            }

            pWriter.close();
            bReader.close();
            isr.close();
            osw.close();
            is.close();
            os.close();

            socket.close();


        } catch (IOException e) {
            System.out.println("Excepció en la connexió: "+e.getMessage());
        }  

    }
}

    Com veiem, una vegada tenim disponible el socket, creem dos fluxos de dades per a llegir i escriure d'aquest:

    InputStream is=socket.getInputStream();
OutputStream hueso=socket.getOutputStream();

    A partir dels fluxos, creem dos fluxos més per a la lectura i escriptura de caràcters:

    InputStreamReader isr=new InputStreamReader(is);
OutputStreamWriter osw=new OutputStreamWriter(os);

    I a partir d'ells per a la lectura i escriptura de línies:

    BufferedReader bReader=new BufferedReader(isr);
PrintWriter pWriter=new PrintWriter(osw);

    Ara, per a demanar al servidor (suposant que es tracta d'un servidor web) un recurs, caldrà escriure en el socket l'ordre corresponent. El protocol HTTP estableix l'ordre GET per a obtindre un recurs. Així doncs, farem:

    String command="GET /"+args[2]+ "\r\n\r\n";
System.out.println("HTTP Request: "+command);
pWriter.println(command);
pWriter.flush();

    Hem creat una ordre HTTP (command), que demana al servidor el document indicat com a tercer argument per la línia d'ordres. Fixeu-vos que el protocol espera dos retorn de línia (de la forma \r\n) en finalitzar la instrucció.

    Aquesta ordre, l'enviem a través de l'objecte de tipus PrintWriter per a escriure la línia completa, i hem fet el flush per a assegurar-nos d'enviar el búffer complet.

    Un vegada hem enviat la petició, llegirem la resposta a través del lector de línies de tipus BufferedReader que hem definit a partir del stream oferit pel socket, i les vam mostrar per pantalla.

    String linia;
while ((linia=bReader.readLine()) != null ){
 System.out.println(linia);
}

    I finalment, només ens quedarà tancar tots els streams oberts, així com el socket:

    pWriter.close();
bReader.close();
isr.close();
osw.close();
is.close();
os.close();
socket.close();

    Tip

    try-wih-resources

    Els recursos de tipus Socket com altres recursos que utilitzen Streams (fitxers, Scanner...) requereixen del seu tancament immediatament després del seu ús

    Per a ajudar-nos a tancar aquest tipus de recursos, Java ens ofereix la declaració try-with-resources, en la qual especifiquem un recurs que haurà de tancar-se després del seu uso.la sintaxi de la declaració try-with -resouceses la següent:

    try(Declaración_e_inicialización_de_recursos){
    ...
    } catch(...) {...}
finally{... }
    Com veiem, es tracta d'un bloc try-catch-finally amb la diferència que s'inclou la inicialització dels recursos que utilitzarem en el try. Per al cas d'un socket, faríem:

    try (Socket socket = new Socket()) {
    socket.connect(socketAddr);
    ...
} catch (IOException e) {
    System.out.println("Excepció en la connexió: " + e.getMessage());
}

    Podeu consultar l'exemple complet en la classe ConnectAndShowWithResources.java

    Aplicacions client-servidor

    En el desenvolupament d'aplicacions client-servidor, hem de tindre en compte els protocols que s'utilitzaran a nivell d'aplicació. Per exemple, en el cas anterior, a pesar que permetem la connexió a un port qualsevol, estem implementant un client del protocol HTTP, per a consultar documents web que demanem al servidor a través de l'ordre GET

    Llavors, quan desenvolupem aplicacions client-servidor. podem trobar-nos un d'aquesta casos:

    • Si només hem de programar el servidor, hem de definir un protocol d'accés al servei; és a dir, hem de definir la forma en què els clients es connectaran a nosaltres.
    • Si hem de programar només la part client, haurem de conéixer quin és el protocol que implementa el servidor al qual ens volem connectar, i
    • Si hem de programar les dues parts, haurem de definir un protocol de comunicació entre la part client i servidor

    Creació d'un servidor d'eco

    Com a primer exemple, crearem un servidor de ressò, que estarà escoltant per un port concret, i emetrà un missatge en resposta a un altre missatge

    El primer que hem de pensar és quin port utilitzarem per a oferir el servei. Com hem comentat abans, ha de ser un port que no siga molt conegut (a partir del 1024), i que no estiga sent utilitzat. Podem saber quins ports estan en ús en el nostre ordinador amb l'ordre netstat -atunp, que ens indica els ports utilitzats localment, les aplicacions que ho utilitzen i el seu estat.

    El codi complet és el següent:

    import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.*;
import java.io.IOException;

import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.BufferedReader;
import java.io.PrintWriter;

public class ecoServer {

    public void listen() throws IOException{
        System.out.println("Iniciant el servidor...");

        ServerSocket listener=null;
        int srvPort=9999;
        try {
            listener=new ServerSocket(srvPort);
        } catch (IOException e) {
            System.out.println("El port "+srvPort+" està ocupato és inaccessible.");
            return;
        }

        // Iniciem un bucle infinit a l'espera de rebre connexions
        while (true){
            Socket socket=listener.accept();

            // L'ordre anterior és bloquejant, quan arriba aci, ha rebut una connexio
            System.out.println("S'ha rebut la connexió");

            // Ara hem de llegir què ens envíen
            InputStream is=socket.getInputStream();
            InputStreamReader isr=new InputStreamReader(is);
            BufferedReader bf=new BufferedReader(isr);
            String linia=bf.readLine();

            String resposta;

            System.out.println("<log> Received... "+linia);
            // Analitzem la línia, i en funció d'aquesta retornem un resultat
            switch (linia){
                case "Hola don Pepito":
                    resposta="Hola don José";
                    break;

                case "Pasó usted por mi casa?":
                    resposta="Por su casa yo pasé";
                    break;
                case "Y vio usted a mi abuela?":
                    resposta="A su abuela yo la vi";
                    break;
                case "Adiós don Pepito":
                    resposta="Adiós don José";
                    break;
                default:
                    resposta="No es reconeix el misstge...";
                    break;
            }

            // Escrivim el resultat a l'stream d'eixida
            OutputStream os=socket.getOutputStream();
            PrintWriter pw=new PrintWriter(os);
            pw.write(resposta+"\n");
            pw.flush();

            pw.close();
            os.close();

        }
    }

    public static void main(String[] args) throws IOException {
        ecoServer es=new ecoServer();
        es.listen();

    }
}

    Com veiem, la funció principal únicament instància un objecte de la classe ecoServer i invoca el seu mètode listen:

    ecoServer es=new ecoServer();
es.listen();

    Aquest mètode listen crea un objecte de la classe ServerSocket, que proporciona el mètode accept, el qual ens informa de quan es rep una connexió en aquest socket de servidor. L'estructura general és la següent:

    ServerSocket listener=null;
int srvPort=9999;
try {
    listener=new ServerSocket(srvPort);
} catch (IOException e) {...}

while (true){
    Socket socket=listener.accept();
    ...
}
    Com veiem, el mètode accept ha d'estar dins del bucle infinit a l'espera sempre de peticions. Una vegada es rep una petició, podem accedir a través del socket als seus respectius streams d'entrada per a obtindre el missatge:

    InputStream is=socket.getInputStream();
InputStreamReader isr=new InputStreamReader(is);
BufferedReader bf=new BufferedReader(isr);
String linia=bf.readLine();

    I al seu stream d'eixida per a escriure la resposta:

    OutputStream os=socket.getOutputStream();
PrintWriter pw=new PrintWriter(os);
pw.write(resposta+"\n");
pw.flush();

    Creació del client d'eco

    El client del nostre servei de ressò serà molt semblant a l'exemple de ConnectAndShow vist anteriorment, amb la diferència que ara sabem el port pel qual escolta el nostre servidor, i no caldrà indicar-lo explícitament:

    import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.*;
import java.io.IOException;

import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.BufferedReader;
import java.io.PrintWriter;

public class ecoClient {
    public static void main(String[] args) {

        if (args.length!=2) {
            System.out.println("Has d'indicar una adreça web i un misstge");
            System.exit(-1);
        }

        String dst=args[0];

        // El port està definit pel protocol
        int portDst=9999;

        Socket socket=new Socket();
        InetSocketAddress socketAddr=new InetSocketAddress(dst, portDst);

        try {
            socket.connect(socketAddr);
            // Connexió realitzada amb èxit
            // Obtenció dels streams d'entrada i eixida
            InputStream is=socket.getInputStream();
            OutputStream os=socket.getOutputStream();


            // Creem fluxos per a la lectura i escriptura de caràcters
            InputStreamReader isr=new InputStreamReader(is);
            OutputStreamWriter osw=new OutputStreamWriter(os);

            // Creem fluxos per a la lectura i escriptura de línies
            BufferedReader bReader=new BufferedReader(isr);
            PrintWriter pWriter=new PrintWriter(osw);

            // Escrivim al socket el missatge
            pWriter.println(args[1]);
            pWriter.flush();


            String linia;
            while ((linia=bReader.readLine()) != null ){
                System.out.println(linia);
            }

            pWriter.close();
            bReader.close();
            isr.close();
            osw.close();
            is.close();
            os.close();

            socket.close();

        } catch (IOException e) {
            System.out.println("Excepció en la connexió: "+e.getMessage());
        }  

    }
}

    Per a utilitzar aquest client amb el servidor de ressò, procedirem de la següent forma:

    1. Una vegada compilats els fitxers ecoServer.java i ecoClient.java, en una terminal obrirem el servidor, amb java ecoServer, i el deixarem funcionant en aquesta terminal.
    2. En una altra terminal, i en el mateix directori, invoquem el client, passant-li una missatge que el servidor estiga preparat per a respondre. Per exemple: java ecoClient "Hola Don Pepito".
    3. Veurem com el servidor ens respon al missatge, i com a mostra a la primer terminal el log del quin ha anat fent
