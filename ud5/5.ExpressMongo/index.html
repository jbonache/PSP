    5. Accés a BBDD MongoDB. Mongoose.

    Node.js i MongoDB

    MongoDB és una base de dades noSQL, orientada a documents i basada en l'emmagatzemament de les seues estructures de dades en documents de tipus JSON amb un esquema dinàmic.

    Un servidor MongoDB pot tindre diverses bases de dades. Cadascuna d'elles conté un conjunt de col·lecions (equiparebles a les taules d'una BDR) i ada col·lecció emmagatzema un conjunt de documents JSON, format per atributs clau-valor (equiparables als registres d'una BDR).

    A grans trets, podem considerar MongoDB com un gran magatzem de dades en format JSON.

    Per altra banda, donat que el format JSON és un format natiu en Javascript, la seua manipulació ens resultarà extremadament senzilla des d'entorns com Node.js. Com hem comentat, aquesta relació és la base de diverses aproximacions full stack com puguen ser els Stacks MEAN (MongoDB+Express+Angular+Nodejs) o MERN (MongoDB+Express+React+Nodejs).

    Accés a MongoDB

    Per a l'accés a MongoDB des de Node.js farem ús de Mongoose, una biblioteca ODM (Object Document Mapping) que s'encarrega de realitzar la traducció o mapat entre els objectes d'una aplicació i els documents d'una BD documental. En aquest cas, Mongoose és una biblioteca que ens permet realitzar el mapat entre documents de la BD Documental MongoDB i objectes Javascript.

    Com sabem, MongoDB és una base de dades NoSQL orientada a documents, i no subjecta a cap esquema, la qual cosa vol dir que podem emmagatzemar qualsevol document JSON en ella, amb esquemes totalment diferents.

    Per altra banda, en MongoDB un document fa referència a cadascun dels objectes dels què volem emmagatzemar informació (el que seríen el registres en el model relacional), que es componen de camps (atributs), i s'organitzen en col·leccions (taules) dins una base de dades.

    Tot i que MongoDB no requereix de cap esquelet o esquema per als documents (com fan les BD relacionals amb les definicions de taula), Mongoose sí que ens obliga, en certa mesura, a definir un esquema a la capa d'aplicació, per tal de fer possible el mapat. Mongoose introdueix el concepte de Model, com a un constructor de més alt nivell, que, a partir d'un esquema, crea una instància d'un document (el que vindríen a ser els registres de la BDR).

    Per tal de fer ús de la biblioteca mongoose al nostre projecte, haurem d'instal·lar-la en aquest, amb:

    npm install mongoose

    Amb el que s'haurà descarregat, i ens hauran aparegut la dependència al fitxer package.json:

    "dependencies": {
    ...
    "mongoose": "^9.8.1"
    }

    Modificació del model

    En l'aplicació d'exemple que hem estat utilitzant hem fet ús d'una estructura de dades JSON com a estructura subjacent al projecte. Anem a veure ara, com modificant només aquesta classe per tal de dotar de persistència a la nostra aplicació de servidor amb MongoDB.

    Note

    Gràcies a que hem organitzat el nostre codi seguint un patró Model-Vista-Controlador, deuriem poder realitzar les modificacions necessàries al model, sense que això afectara a la resta d'aplicació.

    El primer que farem serà situar-nos al model d'usuari (fitxer models/user.js), i començarem important les biblioteques de Mongoose:

    import mongoose from 'mongoose';

    Seguidament, realitzarem la connexió a MongoDB amb mongoose.connect(). La connexió inicial retorna una promesa i convé esperar-la abans d'obrir el port HTTP; si falla, l'aplicació ha de finalitzar amb un error clar. La URI s'obté de l'entorn i no s'escriu en el repositori:

    const mongoUri = process.env.MONGODB_URI ?? 'mongodb://127.0.0.1:27017/test';

try {
    await mongoose.connect(mongoUri, { serverSelectionTimeoutMS: 5000 });
    console.log('Connexió amb MongoDB establida');
} catch (error) {
    console.error('No s\'ha pogut connectar amb MongoDB:', error);
    process.exit(1);
}

mongoose.connection.on('error', error => {
    console.error('Error de MongoDB després de connectar:', error);
});

    Per a una instància local s'utilitza 127.0.0.1 en lloc de localhost, ja que Node 18 i posteriors poden resoldre localhost primer com a IPv6 (::1) mentre MongoDB escolta només en IPv4. Opcions antigues com useNewUrlParser, useUnifiedTopology i keepAlive ja no s'han d'afegir.

    Com sabe, MongoDB emmagatzema les dades en col·leccions amb múltiples documents, que no tenen per què tindre la mateixa estructura. Per altra banda, quan treballem amb objectes en una aplicació, necessitem que aquests pertanguen a una classe, pel que sí que han de tindre la mateixa estructura. Per aquest motiu, Mongoose fa ús de l'objecte Schema, per tal de definir les propietats dels documents, indicant el tipus i les seues característiques, per tal de "forçar" la seua estructura. Així doncs, primerament, haurem de definir un esquema de Mongoose i després definirem un Model constructor. que ens servirà per tal de crear instàncies dels documents de MongoDB.

    Així doncs, anem a definir ara aquest esquema per als usuaris, com a una instància de mongoose.Schema:

    // Definició de l'esquema (equivalent a un bean/xml de mapat),
// a partir de la classe mongoose.Schema.
let Usuarios = new mongoose.Schema({
    nombre: String,
    email: String
});

    I una vegada definit l'esquema, definim el model, associant l'esquema (Usuarios) a una col·lecció de la base de dades, que contindrà documents de tipus usuario. Aquesta col·lecció s'anomenarà usuarios (plural d'usuario), i s'ubicarà de manera predeterminada a la base de dades test:

    // Defnim el model a partir de l'esquema i 
// l'associem a la col·lecció
let users = mongoose.model('usuario', Usuarios);

    En aquest punt, en cas que la col·lecció no existira en MongoDB es crearía automàticament.

    Anem ara a definir tres mètodes per accedir a la informació de la col·lecció: getUsers(), getUser() i addUser(nombre, email). Els dos primers retornaran la llista amb el nom dels usuaris i la informació d'un usuari concreta, i el tercer afegirà un usuari nou.

    Note

    Si contrastem amb el model anterior, per obtindre la llista d'usuaris, directament accedíem sobre el vector d'usuaris, que exportàvem des del model. És més correcte definir un mètode que retorne la informació que necessitem, en lloc de donar accéss a la col·lecció de dades completa.

    • Mètode getUsers(): Aquest mètode realitzarà una consulta per obtenir tots els documents de la col·lecció, projectant-los sobre el nom. Amb el resultat de la consulta, generarà el vector que espera el controlador i el retornarà:
    // Obtenció de la llista d'usuaris
export async function getUsers() {
    let res = await users.find({}, { nombre: 1, _id: 0 });
    if (res) {
        let llista = [];
        for (let usuari of res) {
            llista.push(usuari["nombre"]);
        }

        return llista;
    } else {
        console.log(err);
        return null;
    }
}

    Observeu que per fer la projecció hem indicat {nombre: 1, _id:0}, sense dir què fer amb l'email. Aquestes operacions són projeccions d'inclussió, el que vol dir que hem d'afegir a la projecció només els camps que volem que es mostren, amb valor 1. La resta de camps, no s'inclouran en la projecció. El camp _id, és la única excepció, i sí que s'inclou per defecte a la projecció. Per aquet motiu, si no volem que aparega en la projecció, ho indiquem explícitament també. En cas que excloguerem explícitament l'email ({nombre: 1, email: 0, _id: 0}), ens llançaría l'excepció MongoServerError: Cannot do exclusion on field date in inclusion projection.

    Important

    Una altra observació important que cal fe és que l'hem configurat com un mètode síncron (asyn), i que esperem el resultat de les consultes amb await. Hi ha altres formes de treballar amb les consultes, que seríen més correctes i afavoriríen l'asincronisme, com els callbacks o les promeses.

    Disposeu de més informació sobre Queries emb Mongoose a: https://mongoosejs.com/docs/queries.html

    • Mètode getUser(): Aquest mètode realitza una cerca amb findOne, per tal d'obtindre l'usuari amb un nom donat. Ara, en la projecció sí que volem el nom i l'email, exclourem l'identificador:
    // Obtenció de la informació d'un usuari
export async function getUser() {
    let res = await users.findOne({ "nombre": nombre }, { nombre: 1, email: 1, _id: 0 });
    if (res) {
        return res;
    } else {
        return null;
    }
}
    • Mètode addUser(nombre, email): Aquest mètode rep l'usuari i l'email, i fa ús del mètode create del model per incorporar un nou document a la col·lecció amb aquestes dades.
    // Afegir un usuari
export function addUser(nombre, email) {
    users.create({ "nombre": nombre, "email": email })
}

    Amb tot açò, ja tenim el nostre model llest per utilitzar a la resta d'aplicació.
