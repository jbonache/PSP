    3. MVC del costat del servidor

    El patró MVC

    com sabem, el MVC és un dels patrons utilitzats en l'enginyeria del programari, i organitza les nostres aplicacions en tres capes:

    • Model: responsable de la gestió de les dades,
    • Vista: Responsable de la interfície d'usuari, i el
    • Controlador, que conté la lògica de negoci, des de la gestón d'evenots fins al canvi de vistes o l'accés a les dades

    Aquest és hui dia el patró més utilitzat per a dissenyar aplicacions en Internet, on s'incorpora un component més, el Router, que és qui rep les sol·licituds HTTP i decideix quines accions invocar del controlador.

    Aplicat a serveis i aplicacions web, podríem concretar la funció de la resta de components de la següent manera: El controlador serà qui orquestre la resposta a les peticions de l'usuari: analitza què es demana, cerca les dades o els actualitza en el model, i segons aquests, els insereix en una vista per a proporcionar-los al client.

    Adaptació del servidor web per a usuaris

    Veurem com aplicar aquesta arquitetura al nostre exemple de servidor Express per al registre d'usuaris.

    Model de dades

    En primer lloc, crearem un mòdul específic per al model

    Crearem una nova carpeta en l'arrel que anomenarem model, i dins d'ella, un fitxer users.js:

    servidorWeb/
    `-- models/
        `-- users.js

    Aquest fitxer tindrà la connexió a les dades (en aquest cas, simplement defineix el vector amb un usuari), i els mètodes per a accedir a ells:

    /* Modelo de datos */

// Añadimos `export` delante de los datos o funciones que deseamos exportar

export let usuarios = [{ "nombre": "pepe", email: "pepe@gmail.com" }, ]

export function getUser(nombre) {
    for (let usuario of usuarios) {
        if (usuario.nombre === nombre)
            return { "status": "ok", "data": usuario };
    }
    return null;
}

export function addUser(nombre, email) {
    usuarios.push({ "nombre": nombre, email: email });
}

    Observeu com hem fet ús de export per a indicar que exportarem ** tant el vector d'usuaris com les funcions getUser i addUser

    Ara, per a utilitzar aquests components en el nostre index.js, haurem d'importar-los, de la següent manera:

    // Importamos el modelo
import { usuarios, getUser, addUser } from './models/users.js';

    L'Router

    Separarem la funcionalitat de recollir les peticions que ens arriben del seu processament. Per a això, definirem les tres següents rutes en el nostre fitxer d'índex principal (index.js):

    // Routers
app.get('/api/users{/:nombre}', ObtenerNombresController);
app.post('/api/users', ObtenerDatosUsuarioPost);
app.put('/api/users', AnyadirUsuario);
app.use('*', DefaultController);

    Amb això, recollim les diferents peticions, i associem diferents middlewares, que seran els controladors per a cada tipus de petició

    Controladors

    Definirem els controladors (que en aquest cas, i en retornar objectes JSON integren també les vistes), com les quatre funcions següents:

    // Controladores (y vistas)

function ObtenerNombresController(req, res) {
    let lista = []
    let response;
    let type = "application/json";
    let status;

    if (typeof(req.params.nombre) === typeof(undefined) && typeof(req.query.nombre) === typeof(undefined)) {
        for (let usuario of usuarios) { lista.push(usuario.nombre); }
        response = { "status": "ok", "data": lista };
        status = 200;
    } else {
        let nombre;
        if (typeof(req.params.nombre) !== typeof(undefined)) nombre = req.params.nombre;
        else nombre = req.query.nombre;

        response = getUser(nombre);

        if (!response) response = { "status": "error", "msg": "User not Found" };
    }

    res.type(type);
    res.status(status);
    res.send(response);

}

function ObtenerDatosUsuarioPost(req, res) {

    let nombre = req.body.nombre || null;

    res.status(200);
    let response = getUser(nombre);
    if (!response) response = { "status": "error", "msg": "User not Found" };

    res.send(response);

}

function AnyadirUsuario(req, res) {

    // Para peticiones POST debemos 
    let nombre = req.body.nombre || null;
    let email = req.body.email || null;

    console.log(nombre);
    console.log(email);

    let response;

    if (nombre && email) {
        addUser(nombre, email);
        response = { "status": "ok" }
    } else response = { "status": "error", "errorMsg": "Undefined Data" };

    res.send(response);

}

function DefaultController(req, res) {
    res.send('Error 404. Not Found');
}

    Com podem veure, aquesta és la funcionalitat que ja teníem implementada en l'exemple anterior, però separada en capes. En tractar-se d'un exemple senzill, els controladors s'inclouen en el mateix index.js, però quan aquests comencen a créixer, serà convenient crear un directori específic per als controladors.

    Mapatge a l'objecte Router

    Recordem que l'encaminament consisteix a decidir quin controlador executem perquè genere la resposta a certa petició, mitjançant un middleware o un altre.

    Per a seleccionar l'un o l'altre controlador devem mapear les funcions de Middleware a una URL determinada. Fins ara, el que hem fet ha sigut mapear aquestes funcions a l'objecte aplicació, mitjançant app.use(["url",] FunciónMiddleware) o amb app.[get|post|put](["url",] FunciónMiddleware)

    Una altra forma habitual consisteix en mapear aquestes funcions a un objecte router. Encara que funcionalment tots dos mètodes són equivalents, la diferència s'encuantra en l'organització, ja que el mapatge sobre un router ens permet ser més específics en les rutes, i crear rutes montables i modulars, a més de (com veurem més endavant), aplicar funcions d'autenticació.

    Per a utilitzar un encaminador, hem de crear-lo mitjançant la funció de factoria Router d'Express:

    const router = express.Router();

    Atés que instància d'encaminador suposa tot un sistema de middleware i adreçament complet, es coneix també com miniaplicación

    Per al nostre exemple de gestió de l'agenda, i una vegada creat el router, configuraríem les rutes de la següent manera:

    router.get('{/:nombre}', usuariosController.ObtenerNombresController);
router.post('/', usuariosController.ObtenerDatosUsuarioPost);
router.put('/', usuariosController.AnyadirUsuario);

    Note

    Per a aquest exemple, hem separat els controladors en un mòdul a part, i en lloc de funcions, els hem incorporats com a mètodes estàtics a una classe usuariosController.

    Observeu que hem definit les rutes per als diferents mètodes (GET, POST i PUT) directament en router, i sense especificar la primera part de la URL (/api/usuarios). Això ho configurarem ara en la app:

    app.use("/api/users", router);

    Amb això, el que fem és indicar a l'aplicació que per a les peticions a /api/users, ha d'utilitzar el router que hem definit (observar que utilitza est com Middleware).

    D'aquesta manera, s'atendran les peticions de la mateixa manera que abans, però utilitzant la miniaplicación d'usuaris. D'aquesta manera, podríem definir altres rutes per exemple per a /api/productos que tingueren el seu propi encaminador, controladors i models; en definitiva, una altra miniaplicación

    Note

    Teniu aquest exemple complet en el fitxer servidorWebRouter.zip. Per al seu ús, després de descomprimir-lo heu de fer primer un npm install en la carpeta del projecte.
