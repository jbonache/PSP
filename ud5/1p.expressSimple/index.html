    Servidor web amb Express

    Servidor web amb Express

    Express és un framework per a la creació de la infraestructura d'aplicacions web nodeJS mínima i flexible, que ofereix característiques tant per a les aplicacions web com mòbils, amb una gran quantitat d'utilitats HTTP i middleware, que permet la creació d'APIs sòlides, ràpides i senzilles sobre Node.js, aprofitant les seues capacitats de programació concurrent monohilo i dirigides per esdeveniments.

    Veurem com crearíem un servidor web de la manera més senzilla mitjançant ExpressJS.

    Creació del paquet

    Per a això, en primer lloc, creem una carpeta per al nostre servidor i inicialitzem dins d'ella un projecte nou amb npm:

    $ mkdir servidorHTTP
$ cd servidorHTTP
$ npm init

    Aquesta última ordre ens inicialitza un projecte, preguntant-nos certes dades sobre aquest, que deixarem en els seus valors per defecte, i ens generarà un únic fitxer package.json:

    {
  "name": "servidorhttp",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "",
  "license": "ISC"
}

    Com veiem, especifiquem el nom (name) del paquet, la versió, una descripció opcional, que podem modificar, així com l'identificador del mòdul d'entrada al programa (main), la llicència (license) i els autors. Podem completar aquests camps com desitgem, respectant sempre el format JSON. A més, tenim una secció de scripts configurables per a llançar amb npm. Per defecte es genera el script test, per la qual cosa podem llançar el projecte amb:

    $ npm test

> servidorhttp@1.0.0 test
> echo "Error: no test specified" && exit 1

Error: no test specified

    Si creem el fitxer index.js, per exemple amb el següent contingut:

    console.log("Hola Mundo");

    podrem llançar la nostra aplicació mitjançant:

    $ Node.js index.js

    O bé, si afegim el següent contingut a la secció de scripts:

    "scripts": {
    ...
    "start": "node index.js"
  },

    Podem llançar-ho amb:

    $ npm start

> servidorhttp@1.0.0 start
> node index.js

Hola Mundo

    Note

    Com veiem, hem creat un nou script anomenat start que s'encarrega de llançar la nostra aplicació.

    En aquest punt, és possible que t'estigues preguntant per a què serveix el camp main que especifica el punt d'entrada si hem de crear un script per a la seua execució? El main especifica un identificador de mòdul, que és el punt d'entrada per a aquest quan, una vegada instal·lat, és requerit mitjançant require per un altre mòdul.

    Note

    Pots trobar tota la informació sobre el fitxer package.json en la documentació oficial de Node.js.

    Instal·lació d'Express

    Una vegada creat ja el nostre mòdul, instal·larem Express com a dependència, mitjançant la següent ordre:

    $ npm install express

added 57 packages, and audited 58 packages in 7s

7 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities

    Amb això, s'ha afegit la dependència següent al nostre paquet:

    "dependencies": {
    "express": "^5.1.0"
  }

    Com veiem, la dependència inclou la versió mínima del paquet Express, que s'estableix a la versió actual del paquet.

    A part d'Express, com veiem en la instal·lació, s'han descarregat quasi 60 paquets addicionals, que són dependències del propi Express. L'eixida del ordre mostra també alguns paquets que busquen finançament, així com aquelles vulnerabilitats presents en alguna dependència.

    A més, també s'haurà generat la carpeta node_modules, amb tots els paquets descarregats. Així doncs, si pujarem la nostra aplicació a algun repositori Git, haurem de crear un fitxer .gitignore en el qual s'especifique com a mínim aquest directori node_modules/. En Github podem trobar un exemple de fitxer gitignore complet per a aquesta mena de projectes.

    Note

    Si descarreguem un projecte d'un repositori, haurem d'instal·lar les dependències mitjançant l'ordre:

    npm install

    Creant un servidor bàsic

    Una vegada generat el projecte i descarregades les dependències, incorporem el següent codi al fitxer index.js:

    // Importem Express
const express = require('express');

// Definim app com una aplicació Express.
const app = express();

// Activem els parsers incorporats per a JSON i formularis.
app.use(express.urlencoded({ extended: false }));
app.use(express.json());

// Configurem el servidor per a escoltar pel port 8080.
const server = app.listen(8080, (error) => {
    if (error) throw error;
    console.log('Escoltant pel port 8080');
});

// Definim l'endpoint "/" per a peticions GET.
app.get('/', function(req, res) {
    res.send('Benvingut al servidor');
});

    Note

    L'exemple anterior usa CommonJS. En un projecte nou també podem usar mòduls ECMAScript indicant "type": "module" en package.json. En aquest cas, la importació és:

    import express from 'express';

    No cal instal·lar body-parser per a JSON ni formularis: Express incorpora express.json() i express.urlencoded() des de la versió 4.16. En Express 5, extended és false per defecte; l'indicarem explícitament quan vulguem deixar clara la decisió.

    Amb tot això, ja podem arrancar la nostra aplicació amb npm start per a escoltar peticions pel port 8080, accedint amb el navegador web a localhost:8080. Amb això, de moment només atendrem peticions al recurs arrel, amb el qual obtindrem el missatge Benvingut al servidor. Si intentem accedir a qualsevol altre recurs, obtindrem el missatge Cannot GET /recurs

    Com veiem, el resultat que s'obté és el missatge que indiquem en el res.send dins del callback per a l'endpoint /. Aquest missatge que hem enviat es troba, com veiem en text pla, encara que podria tractar-se també de codi HTML. Per exemple:

    app.get('/', function(req, res) {
    res.send(`<html>
    <head>
        <title>Bienvenido al servidor</title>
    </head>
    <body>
        <h1>Hola! Bienvenido al servidor</h1>
    </body>
</html>`);
});

    Perquè els canvis s'apliquen haurem de parar i tornar a arrancar el servidor. Ara ja podem veure com es representaria aquest codi en el navegador.

    Definició de múltiples endpoint

    Com veiem, l'exemple anterior únicament respon al endpoint /. Express admet tants endpoints com desitgem, per la qual cosa podríem expressar el següent:

    app.get('/', function(req, res) {
    res.send(`Bienvenido al servidor`);
});

app.get('/saludo', function(req, res) {
    res.send(`<html>
    <head>
        <title>Bienvenido al servidor</title>
    </head>
    <body>
        <h1>Hola! Bienvenido al servidor</h1>
    </body>
</html>`);
});

app.get('*', function(req, res) {
    res.send(`Lo siento, no encuentro ${req.url}`);
});

    Com veiem hem inclòs tres endpoints o mètodes de ruta per al mètode GET, mitjançant app.get:

    • El primer, l'endpoint arrel /, al qual accedim directament amb l'host del servidor i el port (http://localhost:8080),
    • El segon, el mètode /saludo, al que accedemos conhttp://localhost:8080/saludo`,
    • I el tercer, compost pel caràcter comodí *, amb el qual coincidiria qualsevol altra ruta, i mostrarà un missatge indicant que no es troba la URL.

    Important

    Adreçament

    Acabem d'introduir el concepte de endpoint o punt final, que no és més que una URI (Identificador de recurs uniforme) o via d'accés juntament amb un mètode de sol·licitud HTTP específic (GET, POST, etc.). Quan parlem d'adreçament, fem referència a com respondrà la nostra aplicació enfront d'aquests endpoints

    Les diferents rutes tindran una o diverses funcions de gestor (callbacks) associades.

    Les rutes, per la seua part tindran la següent estructura:

    app.METHOD(PATH, HANDLER)

    Sent:

    • app, la instància d'express,
    • METHOD el mètode de sol·licitud HTTP (GET, POST, etc).
    • PATH la via d'accés o endpoint en el servidor.
    • HANDLER el callback que s'executa quan una petició coincideix amb la ruta.

    Creació d'un servidor de pàgines estàtiques amb el middleware static

    En l'apartat anterior vam veure com donar resposta a diferents peticions HTTP en el nostre servidor. Veurem ara com crear un servidor web que oferisca contingut estàtic. Per a això utilitzarem el middleware Static

    Generador d'aplicacions Express (express-generator)

    Encara que no ho utilitzarem, és interessant conéixer l'eina express-generator, un generador d'aplicacions que ens permet crear ràpidament un esquelet d'aplicació.

    Disposeu de més informació sobre aquesta eina en la documentació oficial d'Express

    En Express, un middleware és una funció que es pot executar abans o després de gestionar una ruta i que té accés als objectes Request amb la petició, Response amb la resposta i a la funció next(). Aquestes funcions poden utilitzar-se com a mecanismes per a verificar nivells d'accés abans d'accedir a un endpoint, per a gestionar errors o per a validar dades, ens altres.

    El middleware Static és una funció incorporada en Express, que ofereix un servei d'arxius estàtics, com a documents (HTML, JSON), imatges, scripts Javasript, fulles d'estil CSS, etc

    Aquesta funció únicament requerirà un paràmetre, que serà la carpeta que emmagatzemarà aquest contingut estàtic. Generalment, aquesta carpeta sol denominar-se public. Així doncs, una vegada generada aquesta carpeta, indicaríem l'ús del middleware com:

    app.use(express.static('public'));

    Note

    Ara, descàrrega el fitxer de recursos contingut_public.zip i descomprimeix el contingut directament en la carpeta public. Amb això, i una vegada reiniciat el teu servidor hauries de poder accedir al servidor i veure el contingut d'aquesta carpeta.

    Warning

    Notes sobre l'ordre de comprovació de rutes

    Funciona correctament el servidor? On has situat la instrucció app.use(express.static('public'));? Prova a afegir-la en les següents ubicacions:

    • Abans de app.get('/', ...),
    • Abans de app.get('*', ...),
    • Al final del codi

    I intenta accedir al servidor mitjançant localhost:8080 i localhost:8080/index.html. Quines conclusions pots traure de tot això?

    Com veiem, Express cerca els arxius de manera relativa al directori estàtic (public en el nostre cas), per la qual cosa el nom d'aquest directori no forma part de l'URL.

    Si desitjàrem crear diferents directoris per a contingut estàtic podríem invocar diverses vegades al middleware Static:

    app.use(express.static('public'));
app.use(express.static('resources'));

    Amb això, Express bussca els arxius en l'ordre en què hem definit tots dos directoris, per la qual cosa primer buscarà els recursos en public i posteriorment en static

    Si desitgem crer un prefix específic per a accedir a l'un o l'altre mena de recursos, podem usar vies d'accés virtual, especificant la via d'accés on muntar el directori estàtic com a primer argument de app.use. Per exemple:

    app.use(express.static('public'));
app.use('/static-resources', express.static('resources'));

    Amb això, continuaríem accedint al contingut de la carpeta public com a element arrel del nostre lloc, però si desitgem accedir als recursos situats en la carpeta resources, ho farem a través d'URLs del tipus http://localhost:8080/static-resources/nombre_recurso_estatico.

    A més, atés que express.static cerca l'a les carpetes de manera relativa al directori des d'on s'inicia el procés node, si llancem aquest des d'una altra ubicació diferent al directori on es troba el paquet, no trobarà el directori. Per a poder llançar el nostre servidor des de qualsevol altre directori, el més recomanable és utilitzar la ruta absoluta del directori, precedint est de la constant __dirname, de la següent manera:

    app.use(express.static(__dirname + '/public'));
app.use('/static-resources', express.static(__dirname +'/resources'));

    Warning

    Si estem creant el nostre servidor com un ES6 Module (hem indicat "type": "module" en el package.json), no tindrem accés a la constant __dirname, i se'ns mostrarà l'error:

    ReferenceError: __dirname is not defined in ES module scope

    Per a resoldre això, farem ús dels mòduls path i url per a definir les constants __filepath i __dirname de la següent manera:

    import path from 'path';
import url from 'url';

const __filename = url.fileURLToPath(
    import.meta.url);
const __dirname = path.dirname(__filename);

    Amb això ja podrem llançar el nostre projecte des de qualsevol ubicació i tindre accés a les carpetes.
