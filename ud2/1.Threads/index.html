    1. Fils

    Introducció

    Els threads o processos lleugers permeten la creació de programes que executen diverses tasques de manera simultània. Aquesta tècnica de programació multifil fa possible la creació d'aplicacions de tipus multimèdia o client-servidor, entre altres, que requereixen que diversos processos s'executen de manera simultània en un ordinador, com el processament de la imatge, del so, o l'atenció a peticions de manera simultània.

    La principal diferència entre processos i fils és que els fils d'un mateix procés comparteixen els mateixos recursos (memòria, fitxers oberts...). Així doncs, quan creem diversos objectes d'una mateixa classe, pot ser que diversos fils d'execució accedisquen a una dada o objecte concret. Aquesta situació pot portar-nos a situacions no desitjades, per la qual cosa s'ha de tindre especial cura en com accedeixen els diferents fils a aquestes dades compartides.

    En aquesta unitat aprendrem a crear i gestionar aquests fils, així com a establir mecanismes per a evitar situacions inesperades en l'accés als recursos compartits.

    Threads a Java

    Els threads, fils d'execució o processos lleugers, són les unitats més xicotetes de processament que poden ser programades pels sistemes operatius, i que permeten a un mateix procés, executar diferents tasques de manera simultània. Cada fil d'execució executa una tasca concreta, i ofereix així al programador la possibilitat de dissenyar programes que executen funcions diferents de manera concurrent.

    Aquesta tècnica de programació amb fils es coneix com multithreading o multifil, i permet simplificar el disseny d'aplicacions concurrents i millorar el rendiment en la creació de processos.

    Per a crear threads a Java podem optar per dues opcions:

    • Crear una classe que herete de la classe Thread (java.lang.Thread) o bé
    • crear una classe que implemente la interfície Runnable (java.lang.Runnable)

    Encara que tots dos mecanismes són pràcticament equivalents, l'opció recomanada en la documentació de Java és utilitzar la interfície Runnable. Recordem que Java no suporta herència múltiple, i que el més semblant que ofereix són les interfícies. Si creem una classe que descendisca directametne de Thread, no podrà descendir de cap altra. Així doncs, si disposem d'una classe que pertany a una jerarquia i que a més té les característiques i es comporte com un thread, hem d'utilitzar la interfície Runnable

    Creació de fils mitjançant la classe Thread

    Com hem comentat, una de les maneres de crear un fil és creant una classe que descendisca de la classe Thread. A més, aquesta classe implementarà un mètode run() que contindrà el codi amb la lògica que s'executarà en fil.

    El codi corresponent per a això seria:

    public class MiHilo extends Thread{
    public void run(){
        // lógica interna del hilo
    }
}

    I ara, en una altra classe, inicialitzem i executem el fil:

    public class Principal{
    public static void main(String[] args) {
        // Creamos el nuevo thread
        MiHilo t=new MiHilo();

        // Lo ponemos en ejecución
        t.start();  
    }
}

    Important

    Observeu que la lògica del fil es defineix en el mètode run(), però la invocació la realitzem mitjançant el mètode start(), que és qui fa possible l'execució asíncrona de la lògica indicada en el mètode run(). Si s'invocara el mètode run() directament, la seua lògica s'executaria de manera síncrona.

    Creació de fils mitjançant la interfície Runnable

    Tal com hem comentat, la forma recomanable de crear un thread no és definint una subclasse de Thread sinó definint una classe que implemente la interfície Runnable. Per a això farem el següent:

    1. Definir una classe que implemente la interfície Runnable i sobreescriure el mètode public void run(), amb la lògica interna del fil:
    public class ClaseRunnable implements Runnable {
    // Declaración de atributos y métodos

    @Override
    public void run() {
        // lógica interna del hilo
    }
}
    1. Crear el thread. Per a això, creem una instància de la classe claseRunnable i li la proporcionem al constructor de la classe Thread per a crear el nou fil:
    ClaseRunnable objetoRunnable=new ClaseRunnable();
Thread hilo=new Thread(objetoRunnable);
    1. Llançar el fil, invocant al mètode start():
    hilo.start();

    La classe Thread admet múltiples constructors. En el nostre cas, estem utilitzant un constructor al qual li proporcionem una classe que implementa la interfície Runnable, però també podem proporcionar-li un nom al thread, i fins i tot un nom de grup.

    Creació de múltiples fils

    En algunes ocasions necessitarem controlar diversos fils d'execució en la nostra aplicació. En aquest cas haurem d'utilitzar estructures de dades com a vectors o llistes per a emmagatzemar-los.

    • Creació del vector o llista:
    // Como vector
Thread vector_hilos[]=new Thread [longitud];
// Como lista
ArrayList<Thread> lista_hilos=new ArrayList<Thread>();
    • Creació dels fils:
    Thread hilo=new Thread(objetoRunnable);
// Almacenamiento en el vector
vector_hilos[posicion_i]=hilo;
// Almacenamieno en la lista
lista_hilos.add(hilo);

    O bé tot en la mateixa ordre:

    // Almacenamiento en el vector
vector_hilos[posicion_i]=new Thread(objetoRunnable);
// Almacenamiento en la lista
lista_hilos.add(new Thread(objetoRunnable));
    • Llançament dels fils:
    // Desde el vector
vector_hilos[posicion].start();
// Desde la lista
lista_hilos.get(0).start();

    El mètode join

    Tots els programes multifil posseeixen un fil principal. Quan creem un nou fil en el nostre programa, es produeix una bifurcació en la seua execució, que separa el fil original del nou fil.

    A partir d'aquesta bifurcació, l'execució de tots dos fils és independent, de manera que cadascun pot realitzar les seues funcions en paral·lel.

    És possible, que en un moment donat, el fil principal haja d'esperar que finalitzen els fils que ha creat per a seguir amb la seua operativa, o bé per a finalitzar. En aquest cas haurem de posar al fil principal en espera, fins que acaben els fils que ha creat i es puga unificar l'execució de tots dos. Això s'aconsegueix mitjançant el mètode join()

    El mètode join(), deixa al fil que l'ha invocat en estat d'espera, fins que el fil referenciat acaba. El codi per a això seria:

    Thread hilo1=new Thread(objetoRunnable_1);
Thread hilo2=new Thread(objetoRunnable_2);

hilo1.start();
hilo2.start();

//...

hilo1.join();
hilo2.join();

    Com veiem, es generen dos fils a partir de dues instàncies de la classe ClaseRunnable (objetoRunnable_1 i objetoRunnable_2), s'executen, i posteriorment, s'espera que finalitzen tots dos mitjançant el join()

    Gràficament podem veure aquesta relació la següent manera:

    Com veiem, el fil principal llança els dos fils en moments diferents, i posteriorment, invoca al mètode join de tots dos fils per a esperar la seua finalització.

    Atés que l'hilo1 ja ha acabat quan s'invoca el join, s'unifica immediatament amb el fil principal.

    Encara així, el fil principal, segueix en espera fins que finalitza l'hilo2. Quan aquest finalitza, es realitza la unificació amb el fil principal, i segueix l'execució d'aquest.

    Com veiem, el mètode join() suposa una primera aproximació a la sincronització de processos, que tractarem més endavant.

    Important

    El mètode join() pot llançar l'excepció de tipus InterruptedException si el fil al qual s'està esperant s'interromp. En aquest cas, bé haurem de capturar i tractar aquesta excepció amb el seu corresponent bloc try..catch, o bé rellançar-la amb un throws.

    Join() amb temps d'espera

    A vegades és possible que el fil al qual el fil principal està esperant s'haja quedat bloquejat. En aquest cas, és possible que el fil principal quede bloquejat també en aquesta espera.

    Per a evitar aquesta situació, és possible utilitzar un parell de versions del mètode join amb un temporitzador.

    Mètode Descripció
    public final void join(long millis) throws InterruptedException Estableix un temps màxim d'espera en mil·lisegons al fet que finalitze el thread. Si s'indica 0, espera al fet que finalitze.
    public final void join(long millis, int nanos) throws InterruptedException Afig també una quantitat de nanosegons a aquest temps màxim.

    Altres mètodes de la class Thread

    La classe Thread posseeix gran quantitat de propietats i mètodes que podem consultar en la seua documentació oficial. No obstant això, veurem alguns mètode que ens poden ser d'utilitat per a obtindre inf i que ormación sobre els fils:

    Mètode Descripció
    long getId() Retorna l'identificador del thread, consistent en un enter llarg positiu generat automàticament en la creació del fil. Aquest número és únic i inalterable durant el cicle de vida del thread.
    void setName(String Nombre) Permet donar-li un nom al thread.
    String getName(String Nombre) Retorna el nom que li hem assignat al thread.
    Thread currentThread() Retorna un objecte de la classe Thread que representa el fil d'execució actual.
    void setPriority(int prioridad) Permet establir la prioritat del fil, de manera indicativa, ja que el sistema operatiu no està obligat a respectar-la. La prioritat màxima i mínima vénen donades per les constants MAX_PRIORITY i MIN_PRIORITY.
    int getPriority() Retorna la prioritat del fil.
    static boolean interrupted() \ newline boolean isInterrupted() Retornen si el fil actual ha sigut interromput. El mètode interrupted() és un mètode estàtic de la classe Thread, mentre que isInterrupted() és un mètode d'instància. A més, interrupted() restableix l'estat, mentre que isInterrupted() no ho fa.
    boolean isAlive() Retorna cert si el fil està viu.
    public Thread.State getState() Retorna l'estat del fil, que pot ser NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED. Tractarem aquests estats en el següent apartat.
    String toString() Retorna una cadena amb una representació del thread, incloent el nom, la prioritat i el grup en què aquest s'inclou.

    El cicle de vida d'un thread

    Des que es crea fins que finalitza, un thread passa per diferents estats. Podríem definir perquè el cicle de vida d'un thread com el conjunt d'estats pels quals un thread passa des de la seua creació fins a la seua destrucció.

    La classe Thread posseeix una propietat estàtica de tipus enumerat que defineix els possibles estats d'aquesta. En un moment donat, aquests estats poden ser:

    Estat Descripció
    NEW El fil s'ha creat però encara no ha començat la seua execució.
    RUNNABLE El fil es troba en execució o llest per a la seua execució i a l'espera que se li assignen recursos.
    BLOCKED El fil es troba bloquejat en un monitor.
    WAITING El fil es troba espereando indefinidament una acció d'un altre procés.
    TIMED_WAITING El fil es troba espereando un temps concret una acció d'un altre procés.
    TERMINATED El fil ha finalitzat la seua execució.

    Gràficament podem veure els diferents estats en el següent diagrama, així com les diferents transicions entre ells:

    Vegem alguns mètodes més de la classe Thread que ens permeten realitzar canvis en l'estat d'un fil. En apartats següents aprofundirem en la resta

    Mètode Descripció
    void Thread.sleep(long ms) Permet deixar el procés en suspensió durant un temps concret.
    void join() Finalitza el fil d'execució, tornant el control al fil principal que va llançar el fil secundari, amb la possibilitat de triar el temps d'espera en mil·lisegons, com ja hem vist.
    void yield() Torna a un procés en l'estat de llest per a executar (READY en l'esquema), de manera que permet que passen a executar-se altres fils de la mateixa prioritat, encara que el seu estat continua sent RUNNABLE.
    void interrupt() Envia un senyal d'interrupció al fil, indicant que detinga el seu treball i faça una altra tasca.

    Exercici pràctic 1

    En la secció de recursos, tens disponible el programa HolaThreads.java. En ell es defineix la classe MiRunnable, a partir de la qual es poden crear fils. A més, en el seu mètode run(), mostra informació dels fils en si. La classe HolaThreads, que conté el mètode main(), per part seua, crea tres objectes de la classe MiRunnable, i els llança en paral·lel.

    Compila i executa l'exemple i analitza els resultats, prestant especial atenció a aspectes com:

    • L'ordre en què es mostren els resultats
    • Hi ha alguna diferència entre la referència this i hiloActual? En què es diferencia a nivell d'execució this.nombre i hiloActual.getName()?

    Exercici pràctic 2

    A partir del codi de HolaThreads.java de l'exercici anterior, crea un nou programa HolaThreadsParam.java , on es demana:

    • Realitzar les modificacions oportunes perquè s'admeta una llista de noms com a arguments en la invocació (vector args), de manera que es genere un fil per cadascun d'ells.
    • Modifica la lògica interna perquè el nom del Thread estiga associat al nom de l'objecte per al qual s'ha llançat. És a dir, si la propietat nom de l'objecte és Joan, que el seu Thread es cride Thread-Joan. Ací hauràs d'utilitzar el mètode setName.
    • Just abans de finalitzar cada fil, realitza una pausa d'1 segon (mètode sleep) i mostra quan acabe aquesta pausa un missatge de comiat.
    • El programa principal ha d'esperar que finalitzen els fils que genera per a finalitzar.
