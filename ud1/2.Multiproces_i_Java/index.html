    2. Multiprocés i Java

    Introducció

    Una de les característiques principals dels sistemes operatius moderns és el de la multitarea o el multiprocés. El multiprocés permet que diversos processos s'estiguen executant de manera simultània, encara que solament es dispose d'un únic processador, en contraposició als sistemes monoprocés, on els processos s'executen de manera seqüencial.

    Tal com hem vist, quan un procés és creat pel sistema, aquest passa a l'estat de Preparat i és el Planificador, el component del sistema operatiu qui s'encarrega de decidir quin procés, d'entre tots els preparats és atés pel processador. Quan un procés passa de preparat a En execució (o actiu), retira de la CPU el procés que es trobarà en execució, retornant-lo a la cua de preparats. Aquest component planificador i els algorismes de planificació són el cor de la capacitat de multiprocesament dels sistemes actuals.

    D'altra banda, i centrant-nos ja en el món de la programació, abordarem el desenvolupament de programes que puguen implementar diversos processos o fils d'execució, i col·laboren entre si per a dur a terme una tasca, això és, la programació concurrent.

    La programació concurrent pot ser de dos tipus: paral·lela o distribuïda.

    • La programació paral·lela consisteix en la creació de programes que s'executen en un únic ordinador, tinga o no diversos processadors. Evidentment, amb diversos processadors, el rendiment serà major. En cas que únicament es dispose d'un processador, es reparteix el temps de procés entre les diferents tasques, simulant que treballen alhora, en paral·lel.
    • La programació distribuïda consisteix en la creació de programari que s'executa en diferents ordinadors, i que es comuniquen a través d'una xarxa. En el següent apartat, farem una introducció a la creació de processos a Java, i les diferents classes que els representen.

    Processos a Java

    Ens centrarem en la creació de processos a Java. Mitjançant les classes ProcessBuilder i Runtime, Java ens permetrà executar ordres en la terminal, generant processos que seran gestionats mitjançant la classe Process

    Creació de processos a Java: La classe processBuilder

    La classe java.lang.ProcessBuilder ens permet llançar qualsevol executable des de Java. Per a això, una vegada creada una instància de ProcessBuilder, establim certs atributs del procés, i creem aquest mitjançant el mètode Start

    En altres paraules, podríem dir que ProcessBuilder, com el seu nom indica és un Constructor o Generador de processos.

    Per a crear una instància d'un ProcessBuilder, podem utilitzar el constructor de la següent manera:

    • Un constructor buit, sense arguments:
    ProcessBuilder pb = new ProcessBuilder();
    • Un constructor al qual li proporcionem un String, amb l'ordre a executar:

    ProcessBuilder pb = new ProcessBuilder("firefox");
    * Un constructor al qual li proporcionem una llista de Strings, amb l'ordre a executar i els seus arguments:

    ProcessBuilder pb = new ProcessBuilder("firefox", "https://www.google.es");

    Precaució

    Hem de tindre en compte que l'ordre que anem a llançar es trobe en alguna carpeta inclosa en el PATH, de la mateixa manera que quan el llancem a través de la terminal. En cas contrari, haurem d'especificar la ruta completa a l'executable.

    Una instància de ProcessBuilder, pot a més gestionar els següents atributs a través dels mètodes indicats per a això:

    Atribut Descripció
    command La llista amb l'ordre que desitgem llançar i els seus arguments. Una vegada creat un ProcessBuilder, podem modificar aquesta llista mitjançant l'atribut command. Per a accedir a ell, utilitzarem el mètode command(), sense arguments per a obtindre el seu valor i amb arguments per a establir-los.
    environment Conté un mapa de les diferents variables d'entorn. Inicialment serà una còpia de les variables d'entorn del procés actual. Per a accedir a ell, utilitzarem el mètode environment().
    Directory El directori de treball on s'executarà l'ordre. Si no s'especifica, per defecte utilitza el directori actual del procés.
    InputStream, OutputStream i ErrorStream Representen l'entrada, eixida i eixida d'error estàndard del procés, i pot ser modificades mitjançant els mètodes redirectInput, redirectOutput i RedirectError. Ho tractarem amb l'E/S més endavant.

    Vegem un exemple de com llançar el navegador web Firefox mitjançant un ProcessBuilder (fitxer Lanzador.java):

    public class Lanzador {
    public static void main(String[] args) {
        try {
            // Definimos un vector de Strings con la orden
            // y los argumentos. En este caso, lanzamos la orden 
            // firefox y una URL como argumento.
            String app[] = {"firefox", "https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/ProcessBuilder.html"};

            // Creamos el ProcessBuilder
            ProcessBuilder pb = new ProcessBuilder(app);

            // Para lanzar el proceso debemos utilizar el método start.
            pb.start();
        } catch (IOException e) {
            e.printStackTrace();
        }

    }
}

    Hem de destacar que el procés no es crea fins que s'invoca al mètode start del processBuilder. D'aquesta manera, si invoquem, per exemple dues vegades el mètode start, crearem dues instàncies de la classe Process, i per tant, dos processos diferents.

    D'altra banda, s'ha de tenir en compte que el mètode start() pot llançar una excepció d'Entrada i Eixida (IOException), per la qual cosa hem de tractar aquesta adequadament, bé mitjançant captura o propagació.

    La classe Process

    La classe java.lang.Process és una classe abstracta que encapsula la informació sobre l'execució d'un procés.

    Quan invoquem al mètode start d'un ProcessBuilder, aquest ens retorna una instància de Process, amb la informació sobre el procés llançat. Aquesta classe pot utilitzar-se per a realitzar operacions d'entrada i eixida dels processos, comprovar si aquest ha finalitzat, el seu estat de finalització, o bé enviar-li un senyal per a eliminar-lo forçosament.

    Vegem com podem, per exemple, llançar dues instàncies del mateix procés, i obtindre informació associada als processos. Per a això, utilitzarem el següent exemple lanzador2.java:

    import java.io.IOException;

public class Lanzador2 {
    public static void main(String[] args) {
        try {
            // Definimos un vector de Strings con la orden
            // y los argumentos. En este caso, lanzamos la orden
            // firefox y una URL como argumento.
            String app[] = {"firefox", "https://docs.oracle.com/en/java/javase/25/core/process-api1.html"};

            // Creamos el ProcessBuilder
            ProcessBuilder pb = new ProcessBuilder(app);

            // Crearemos dos objetos de tipo Process para almacenar 
            // los procesos devueltos por cada una de las invocaciones a start.
            Process p1=pb.start();
            Process p2=pb.start();

            // Mostramos el PID de los procesos
            System.out.println("PID del proceso 1: "+p1.pid());
            System.out.println("PID del proceso 2: "+p2.pid());
        } catch (IOException e) {
            e.printStackTrace();
        }

    }
}

    En ell, hem creat dos objectes de tipus Process, on guardem els valors retornats per ambdues invocacions al mètode start del ProcessBuilder:

    Process p1=pb.start();
Process p2=pb.start();

    I mitjançant el mètode .pid() (incorporat en la versió 9 de Java), podem obtindre el PID de cada procés, i comprovar que cada invocació a start ha generat un procés diferent.

    System.out.println("PID del proceso 1: "+p1.pid());
System.out.println("PID del proceso 2: "+p2.pid());

    Cal tindre en compte, que a diferència de Bash, els processos creats d'aquesta forma no tenen una consola associada (tty), per la qual cosa no podem redirigir les entrades o eixides estàndard (stdin, stdout i stderr). Per a això, podem accedir a través de streams oferits per diversos mètodes de la classe Process. Aprofundirem en això més endavant.

    Alguns dels mètodes més interessants de la classe Process són els següents:

    Mètode Descripció
    int exitValue() Retorna el codi d'eixida del procés executat.
    Boolean isAlive() Comprova si el procés fill segueix en execució.
    int waitFor() Espera que el procés fill finalitze. El valor sencer que s'obté és el codi d'eixida del procés.
    Boolean waitFor(long timeOut, TimeUnit unido) Es tracta d'una sobrecàrrega del mètode anterior, on podem especificar el temps d'espera. Retornarà cert si el procés segueix en execució després del temps indicat i fals en cas contrari.
    void destroy()
    void destroyForcibly() Forcen la terminació del procés, de manera controlada (SIGTERM) o forçosa (SIGKILL).

    En el següent exemple Lanzador3.java, s'il·lustren alguns d'aquests mètodes de la classe Process:

    import java.io.IOException;
import java.util.concurrent.TimeUnit;

public class Lanzador3 {
    public static void main(String[] args) {
        try {
            // Creación del processBuilder
            String app[] = {"firefox", "https://docs.oracle.com/en/java/javase/25/core/process-api1.html"};
            // Otras alternativas para lanzar, por ejemplo un editor de texto
            // Linux: Escritorio KDE-Plasma
            // String app[] = {"kwrite", "ejemplo.txt"};
            // Linux: Escritorio Gnome
            // String app[] = {"gedit", "ejemplo.txt"};
            // Windows
            // String app[] = {"notepad.exe", "ejemplo.txt"};

            ProcessBuilder pb = new ProcessBuilder(app);

            // Definimos e instanciamos el proceso
            Process p = pb.start();

            // Esperamos 3 segundos.

            // El método waitFor espera el tiempo indicado, y 
            // retorna un valor lógico, incicando si el proceso
            // sigue vivo transcurrido este tiempo.
            // Dado que este método puede generar una excepción
            // de tipo InterruptedException, añadimos ésta 
            // a la cláusula catch
            Boolean isProcessDead = p.waitFor(3, TimeUnit.SECONDS);

            // Si el proceso no se ha destruido antes de 3
            // segundos, le enviamos la señal SIGTERM (p.destroy)
            if (!isProcessDead) {
                System.out.println("Destruyendo la aplicación");
                p.destroy(); // Sugerencia: Puedes usar destroyForcibily y 
                             // comprobar el resultado.
            }

            // Dado que la destrucción del proceso no es inmediata,
            // esperaremos a que éste finalice completamente. Para ello
            // utilizamos el método isAlive, que devuelve si el proceso
            // sigue vivo o no.
            // Si el proceso sigue vivo, esperaremos un milisegundo, y 
            // mostraremos un mensaje.

            while (p.isAlive()) {
                System.out.println("El proceso sigue vivo. Espero un milisegundo.");
                p.waitFor(1, TimeUnit.MILLISECONDS);
            }


            System.out.println("El proceso ha finalizado con la salida: "+p.exitValue());
        } catch (IOException | InterruptedException e) {
            e.printStackTrace();
        }

    }
}

    La interfície Processhandle.Info

    La interfície Processhandle.Info ens permet obtindre informació addicional sobre un procés.

    Per a obtindre aquesta informació, únicament haurem d'accedir al mètode info() de la classe Process:

    ProcessHandle.Info informacion = p.info();

    Aquesta interfície defineix els següents mètodes:

    Mètode Descripció
    String[] arguments() Retorna un vector de Strings amb la llista d'arguments.
    String command() Retorna un String amb el path executable del procés.
    String commandLine() Retorna un String amb la línia dl'ordre introduïda, concatenant l'ordre i els arguments.
    Instant startInstant() Retorna l'hora d'inici del procés en un objecte de tipus Instant.
    Duration totalCpuDuration() Retorna un objecte de tipus Duration amb el temps de CPU acumulat pel procés.
    String user() Retorna una cadena de text amb el nom de l'usuari que va llançar el procés.

    En el següent exemple Lanzador4.java, podem veure un exemple d'ús dels mètodes anteriors i l'ús d'aquesta interfície.

    import java.io.IOException;
import java.util.concurrent.TimeUnit;

public class Lanzador4 {
    public static void main(String[] args) {
        ```java
        try {
            // Creació del ProcessBuilder
            String app[] = {"spotify"};

            ProcessBuilder pb = new ProcessBuilder(app);

            // Definim i instanciem el procés
            Process p = pb.start();

            // Obtenim la informació
            ProcessHandle.Info pInfo = p.info();

            System.out.println("Usuari que ha llançat el procés: " + pInfo.user().get());
            System.out.println("Ordre executada: " + pInfo.commandLine().get());
            System.out.println("Inici d'execució: " + pInfo.startInstant().get().toString());

            Duration t = pInfo.totalCpuDuration().get();
            System.out.println("Temps (en ms) CPU utilitzat >> " + t.toMillis() + " ms");

        } catch (IOException e) {
            e.getMessage();
        }
    }
}

    La classe java.lang.Runtime

    L'API de Java per a la gestió de processos, a més de les classes ProcessBuilder i Process, es completa amb la classe Runtime, que encapsula l'entorn d'execució d'un procés.

    Atés que també és una classe abstracta, no pot ser instanciada directament, i per a usar-la haurem de fer ús del mètode estàtic Runtime.getRuntime()

    Entre els diferents mètodes que tenim disponibles en aquesta classe, podem destacar:

    Mètode Descripció
    int availableProcessors() Retorna el nombre de processadors disponibles per a la JVM.
    Process exec(ordre) Permet executar l'ordre indicat. Admet diferents signatures, per a indicar ordre, arguments o entorn.
    void exit() Finalitza la màquina virtual de Java actual, de manera controlada
    long freeMemory() Retorna la quantitat de memòria disponible en la JVM.
    void gc() Permet invocar al recol·lector de fem de la JVM, encara que no és una bona pràctica.
    long maxMemory() Retorna la quantitat màxima de memòria que pot ser usada per la JVM.
    long totalMemory() Retorna la quantitat total de memòria en la JVM.

    A tall d'exemple, disposeu del següent exemple EjemploRuntime.java, on s'ofereix certa informació sobre l'entorn d'execució del procés actual, així com l'efecte d'utilitzar el recol·lector de fem de la JVM sobre aquesta memòria.

    public class EjemploRuntime {

    // Definimos r como la referencia al entorno de ejecución actual
    private Runtime r = Runtime.getRuntime();

    private void InfoCPU() {
        // r.availableProcessors() nos indica los procesadores que tenemos disponibles
        System.out.println("Procesadores disponibles: " + this.r.availableProcessors());
    }

    private void InfoMem() {

        // r.totalMemory() nos indica la cantidad de memoria reservada para la JVM
        System.out.println("Memoria Total: " + this.r.totalMemory());

        // r.freeMemory() nos indica la memoria libre en la JVM
        System.out.println("Memoria Libre: " + this.r.freeMemory());

        // Para calcular la memoria ocupada, restamos 
        // la memoria libre a la memoria total
        System.out.println("Memoria ocupada: " + (this.r.totalMemory() - this.r.freeMemory()));
    }

    private void InvocarGB() {
        // Método para invocar al Garbage Collector
        this.r.gc();
    }

    private void ExecutarProces() {
        // Método para executar un process, com ProcessBuilder
        String app[] = {"spotify"};
        try {
            this.r.exec(app);
        } catch (IOException ex) {
            System.out.println(ex.getMessage());
        }
    }

    public static void main(String[] args) throws Exception {

        EjemploRuntime ejRt = new EjemploRuntime();

        // Mostramos información sobr la CPU
        ejRt.InfoCPU();

        // Mostramos el estado actual de la memoria de la JVM
        System.out.println("\n---------Estatdo inicial----------");
        ejRt.InfoMem();


        // Ahora vamos a crear varios objetos para generar memoria, 
        // y observar cómo van ocupándola.
        for (int y = 0; y <= 10000; y++) {
            new Object();
        }

        System.out.println("\n-----Estado después de crear 10.000 objetos:-----");
        ejRt.InfoMem();

        // Ahora invocamos al Garbage Collector, para que
        // elimine las referencias no usadas
        ejRt.InvocarGB();

        // Y volvemos a obtener los mismos datos
        System.out.println("\n-----Estado después de invocar al recolector de basura-----");
        ejRt.InfoMem();

        //I, finalment, executem un process
        System.out.println("\n-----Execució d'un nou proces-----");
        ejRt.ExecutarProces();
    }
}

    Com podeu veure, la classe Runtime disposa d'un mètode exec, que permet executar ordres, retornant també un objecte de la classe Process, que encapsula la informació sobre l'execució del procés. Així doncs, amb el mètode exec de Runtime, disposem d'una altra manera de crear processos, alternativa a ProcessBuilder.start(), encara que ProcessBuilder és l'opció més aconsellada per aportar un major control sobre els processos.
