    3. Programació asíncrona

    Concurrència en Node.js

    Javascript és un llenguatge asíncron i concurrent. Què signifiquen aquests dos conceptes?

    • Asíncron: La programació tradicional es basa en el paradigma de programació seqüencial, on un programa és una seqüència d'instruccions que s'executen ordenadament, i una operació no comença fins que no acaba l'anterior. Es tracta doncs d'un model síncron. Enfront d'això, la programació asíncrona dóna la possibilitat que algunes operacions retornen el control de l'execució al programa principal abans d'haver finalitzat, la qual cosa agilita el procés d'execució.
    • Concurrent: la concurrència permet que diverses tasques progressen durant un mateix interval de temps. En un sol fil s'intercalen quan una operació cedeix el control; amb diversos fils o processos també poden arribar a executar-se en paral·lel.
    • Paral·lel: dues o més tasques s'executen literalment al mateix instant en diferents nuclis. La concurrència tracta de l'estructura i coordinació de les tasques; el paral·lelisme, de la seua execució simultània.

    Llavors, el fet que javascript siga asíncron i concurrent significa que les instruccions no tenen per què seguir un ordre seqüencial, de manera que no cal esperar que acaben certes instruccions per a iniciar l'execució uns altres, i que a més, només s'està executant una instrucció en un moment donat.

    Javascript (i per tant Node.js) fan ús del que es coneix com event loop o bucle d'esdeveniments, que és el component encarregat de coordinar l'execució, els events i els callbacks. Veiem alguns d'aquests conceptes amb un exemple:

    function saluda(nombre) {
    console.log("Hola " + nombre);
}

for (let i = 0; i < 5; i++) {
    setTimeout(function() {
        saluda(i);
    }, 500 - i * 100);
}

process.nextTick(function() { saluda("Prioritario 1") });
process.nextTick(function() { saluda("Prioritario 2") });

console.log("Fin de la ejecución");

    Analitzem l'exemple: * Definim una funció saluda, que rep un paràmetre nomene, i escriu en la terminal "Hola", seguit del nom que li passem. * Posteriorment, llancem un bucle que compta de 0 a 5, i dins, defineix un timeOut. La funció setTimeOut el que fa és posar en marxa un temporitzador, que llança una funció en véncer est:

     setTimeout(funcion, tiempo_en_ms);
    • Com veiem, la funció que s'executa en véncer el temporitzador (es tracta d'una funció anònima, ja que no té nom), el que fa és invocar a la funció saluda, passant-li com a paràmetre el valor i de control del bucle. Aquestes funcions que es llancen com a resposta a un esdeveniment (com és el cas del venciment del temporitzador) es denominen funcions de retorn o de callback.
    • A més, al segon paràmetre de la funció setTimeOut li passem el temps que tardarà en véncer est. En l'exemple, hem indicat que aquest temps siga major com més xicotet siga el valor de i, segons la fórmula $500-i*100$.
    • S'han afegit al final dues instruccions process.nextTick, que afigen dues funcions també a executar. Després aprofundirem més en aquestes funcions.
    • I finalment, vam mostrar per pantalla un missatge indicant que ha finalitzat l'execució del programa principal.

    Si llancem ara el script, el resultat és el següent:

    Fin de la ejecución
Hola Prioritario 1
Hola Prioritario 2
Hola 4
Hola 3
Hola 2
Hola 1
Hola 0

    Si ens adonem, dóna la sensació que les ordres s'han executat en ordre pràcticament invers al que esperaríem en la programació seqüencial tradicional. Veurem el per què de tot això.

    L'event Loop o bucle d'esdeveniments

    Nodejs gestiona la concurrència mitjançant un únic fil d'execució, de manera que el primer que s'executa és el programa principal. Si durant l'execució d'aquest programa principal es produeixen certs esdeveniments, aquests s'afigen a una cua d'esdeveniments

    En aquest moment, entra en acció el Event Loop, que és un bucle que està sempre en execució, i que té la missió de vigilar la cua d'events i invocar els callbacks corresponents. Quan un callback finalitza, retorna el control al bucle d'esdeveniments perquè continue gestionant la resta de cua. Si durant l'execució es produeix un altre esdeveniment, aquest esdeveniment s'afig a la cua sense interrompre l'execució actual. D'aquesta manera ens assegurem que una funció que es llança com a resposta a un esdeveniment comença i acaba, evitant-nos així accessos concurrents a seccions crítiques i altres problemes de concurrència de la programació seqüencial. Quan la cua d'esdeveniments es trobe buida, es retorna el control al sistema operatiu.

    Note

    Disposeu de més informació sobre el bucle d'esdeveniments en l'article Javacript Asíncron de LemonCode.

    Promeses en ES6

    Les Promises o Promeses són objectes que representen l'estat de finalització d'una operació asíncrona. A pesar que podem crear promeses mitjançant el seu constructor, el més habitual serà ser "consumidors" de promeses que ens retornen les funcions asíncrones.

    Les promeses s'utilitzen com a alternativa a les funcions de callback, de manera que aquestes funcions de callback siguen funcions que s'executen com a mètodes dels objectes Promesa.

    Exemple

    Veiem un exemple de creació i ús de promeses. Partim del següent codi amb funcions de callback:

    function divide(dividendo, divisor, cbOk, cbErr) {
    if (divisor == 0) cbErr("División por cero!");
    else cbOk(dividendo / divisor);
}

let a = 10;
let b = 0;

divide(
    a,
    b,
    function(result) {
        // Callback si la función tiene éxito
        console.log("El resultado de " + a + "/" + b + " es " + result);
    },
    function(error) {
        // Callback si la función falla
        console.log("Error: " + error);
    });

    com veiem, tenim la funció divide que comprova primerament que el divisor no siga zero. Si el divisor és 0, invoca la funció de callbak cbErr, llançant un missatge d'excepció. En cas que el divisor no siga zero, invocarà la primera funció de callback CbOk passant-li el resultat.

    D'aquesta manera, quan invoquem la funció divide, li passem com a arguments el dividend, el divisor, així com una funció de callback a executar si tot és correcte, i una altra per a quan apareguen errors.

    Per a realitzar aquesta funció amb promeses, faríem el següent:

    function divide(dividendo, divisor) {
    return new Promise((resolve, reject) => {
        if (divisor == 0) reject("División por cero!");
        else resolve(dividendo / divisor);
    })
}

let a = 10;
let b = 0;

divide(a, b)
    .then(result => {
        console.log("El resultado de " + a + "/" + b + " es " + result);
    })
    .catch(error => {
        // Callback si la función falla
        console.log("Error: " + error);
    })

    Analitzem el codi:

    function divide(dividendo, divisor) {
    return new Promise((resolve, reject) => {
        if (divisor == 0) reject("División por cero!");
        else resolve(dividendo / divisor);
    })
}

    Com veiem, ara la funció divide rep únicament el dividend i el divisor, sense cap funció de callback. En lloc d'això, el que fa és retornar un objecte de tipus Promise. Al constructor d'aquesta classe li hem de passar una funció anònima (en forma de funció fletxa en l'exemple), que rebrà dues funcions més: resolve i reject. La primera s'usarà per a retornar informació en cas d'èxit i la segona per a informar d'alguna excepció.

    Veiem ara la part interessant, en la qual fem de consumidors d'aquestes promeses:

    divide(a, b)
 .then(result => {
 console.log("El resultado de " + a + "/" + b + " es " + result);
 })
 .catch(error => {
 // Callback si la función falla
 console.log("Error: "+error);
 }

    En l'exemple hem invocat directament la funció divideix, passant-li només el dividend i el divisor. Com hem comentat, aquesta funció ens retornava un objecte de tipus Promise. Doncs bé, aquest objecte disposa de dos mètodes: then i catch, que serveixen per a indicar què volem fer en cas que la promesa es resolga exisosament, en el cas de then, o què volem fer si aquesta és rebutjada, en el cas del catch. Com veiem, això s'indica dins de cada mètode amb una funció.

    Important

    Resolució d'una promesa

    Un objecte de tipus promesa posseeix tres estats:

    • Pendent (pending),
    • Resolta (fullfilled), o
    • Rebutjada (rejected)

    Quan es crea un promesa dins d'una funció asíncrona, aquesta es troba en estat Pendent. Quan la funció té preparada la resposta (el que seria un return) en una funció síncrona, si aquesta no ha produït cap excepció, s'invoca al mètode resolve de la promesa, passant aquesta a estat resolta. Diem que en aquest moment, es resol la promesa (aquesta nomenclatura la utilitzarem de manera freqüent al llarg del text). En cas que s'haja produït alguna excepció, s'invocarà al mètode reject, de manera que la promesa es rebutja (passa en estat rebutjat).

    Avantatges amb l'ús de promeses

    Com veiem, es tracta de realitzar crides asíncrons d'una forma diferent a com utilitzàvem els callbacks, que presenta certs avantatges:

    Garanties

    Les promeses ens garanteixen:

    • Que les funcions de callback no s'invocaran abans que acabe l'execució actual del bucle d'esdeveniments de Javascript,
    • Que les funcions de callback afegides amb .then, s'invocaran després que la promesa es resolga, amb èxit o fracàs,
    • Que es poden afegir múltiples funcions de callback invocant a .then diverses vegades, per a ser executades en l'ordre d'inserció

    Encadenament

    L'encadenament ens permet executar dues operacions asíncrones seguides i en ordre. Atés que el resultat de l'execució de .then és una altra promesa, podem utilitzar diversos .then encadenats (cadena de promeses), de manera que els resultats (o la promesa resultant) d'un es passen com a entrada al següent. Ací és on veiem el vertader potencial de les promeses: la funció .then, ens retorna una promesa nova, diferent a l'original, de manera que ofereix un nou mètode .then per a tractar els resultats. Amb l'encadenament evitem perquè el temut callback hell o pyramid of doom

    Exemple

    Vegem el següent codi JS que utilitza callbacks per a emplenar un vector amb una llista de la compra:

    const llistaCompra = []

function crearLlista() {

    setTimeout(function() {
        llistaCompra.push('Arros');

        setTimeout(function() {
            llistaCompra.push('Bajoqueta');

            setTimeout(function() {
                llistaCompra.push('Garrofó');

                setTimeout(function() {
                    llistaCompra.push('Pollastre');
                }, 1000);
            }, 1000);
        }, 1000);
    }, 1000);
}

crearLlista();
console.log(llistaCompra.toString()); // Eixida : []

    Si executem el codi anterior, observarem que aquest no mostra res. La causa es deu al propi funcionament del bucle d'esdeveniments. Analitzem el codi.

    El codi principal es compon d'una invocació a crearLlista(), i el console.log del resultat. Dins de crearLlista, el que es fa és establir un temporitzador, que al cap de 1000 ms (un segon), dispara una funció que afig el primer element a la llista:

    function crearLlista() {

    setTimeout(function() {
        llistaCompra.push('Arros');
        ...
    }, 1000);
}

    Atés que aquest esdeveniment s'afig a la cua, registrant també el corresponent callback, el codi del programa principal, en el qual s'inclou el console.log ja s'ha executat quan s'afig l'element al vector.

    Per a resoldre això, examinem el flux en el qual s'executaran les diferents funcions, i ens assegurem que el processament final (el console.log) s'executa al final.

    El següent codi resol doncs el problema:

    const llistaCompra = []

function crearLlista() {

    setTimeout(function () {
        llistaCompra.push('Arros');

        setTimeout(function () {
            llistaCompra.push('Bajoqueta');

            setTimeout(function () {
                llistaCompra.push('Garrofó');

                setTimeout(function () {
                    llistaCompra.push('Pollastre');
                    console.log(llistaCompra.toString()); 
                    // Eixida : [Arros,Bajoqueta,Garrofó,Pollastre]

                }, 1000);
            }, 1000);
        }, 1000);
    }, 1000);
}

crearLlista();

    No obstant això, com veiem, ens trobem davant un encadenament de crides, conegut com Callback Hell, que com veiem, sol dificultar bastant la lectura i comprensió del codi.

    Una millor solució la tenim amb l'ús de Promeses. Vegem com adaptar el codi anterior per a utilitzar aquestes. Vam mostrar el codi comentat amb les explicacions:

    const llistaCompra = []

// En primer lugar, creamos una función que añade un item
// proporcionado como argumento a la lista de la compra. 
// Para ello, establece también el temporizador, para que
// esto se haga al cabo de un segundo, pero ahora
// lo que devolvemos es una promesa.
//
// La resolución de esta promesa consistirá pues en
// añadir el ítem proporcionado a la lista.

function afigItem(item) {
    return new Promise(resolve => setTimeout(function() {
        resolve(llistaCompra.push(item));
    }, 1000));
}

// En segundo lugar, Vamos añadiendo los diferentes
// componentes de la lista mediante la función anterior.
// Cada invocación a esta función devuelve una promesa, 
// cuyo resultado tratamos con la función then.
// Dado que en cada then añadimos otra invocación, podemos
// encadenar todas estas promesas del siguiente modo.

afigItem("Arros")
    .then(function() {
        return afigItem("Bajoqueta");
    })
    .then(function() {
        return afigItem("Garrofó");
    })
    .then(function() {
        return afigItem("Pollastre");
    })
    .then(function() {
        console.log(llistaCompra.toString());
    })

    async/await

    La versió EcmaScript 2017 va introduir la millora sintàctica async/await, que permet treballar amb funcions asíncrones com si treballàrem amb funcions síncrones.

    Cal remarcar que es tracta d'una millora sintàctica, construïda sobre promeses, de manera que les funcions que retornaven promeses són exactament iguals que abans.

    Així doncs, seguint amb l'exemple anterior, en primer lloc, deixem la funció afigItem tal com la teníem.

    function afigItem(item) {
    return new Promise(resolve => setTimeout(function() {
        resolve(llistaCompra.push(item));
    }, 1000));
}

    Posteriorment, definim una funció crearLlista que invocarà la funció afigItem tantes vegades com items calga incorporar, proporcionant-li aquests

    La diferència és que ara precedirem cada invocació amb la paraula clau await, de manera que la funció asíncrona queda suspesa fins que la promesa es resol, sense bloquejar el bucle d'esdeveniments. Per a usar await dins d'una funció l'hem de declarar amb async:

    async function crearLlista() {
    await afigItem("Arros");
    await afigItem("Bajoqueta");
    await afigItem("Garrofó");
    await afigItem("Pollastre");
    console.log(llistaCompra.toString());
}

crearLlista();
