    Parlant de l'encadenament de promeses..

    Podem fer l'encadenament després d'una captura d'error?

    Després de capturar una fallada, amb un catch, podem continuar fent l'encadenament, de manera que puguem realitzar noves accions fins i tot després que es produïsca un error en la cadena

    Veiem el següent codi d'exemple:

    new Promise((resolve, reject) => {
        console.log("Punto 1");
        resolve();
    })
    .then(() => {
        throw new Error("Error 1");
        console.log("Punto 2");
    })
    .catch(() => {
        console.log("Punto 3");
    })
    .then(() => {
        console.log("Punto 4");
    });

    Que retorna:

    Punto 1
Punto 3
Punto 4

    Propagació d'errors

    Si fem una comparació entre la implementació amb callbacks i amb promeses de l'exemple d'encadenament, veurem que la funció funcioFalladaCallback que gestiona els errors apareix diveres vegades amb la implementació amb callbacks, mentre que amb promeses, només apareix al final de la cadena de promeses. Com podem comprovar l'estructura és semblant a com es gestionen els errors en estructures síncrones com el try..catch, i funciona de manera que quan es produeix una excepció dins de la cadena de promeses, l'execució es per a i es recorre la cadena buscant gestors d'errors (catch)

    El codi d'exemple anterior:

    funcio1()
    .then(resultado => {
        return funcio2(resultado);
    })
    .then(resultat2 => {
        return funcio3(resultat2);
    })
    .then(resultat3 => {
        // Tratamiento de resultat3
    })
    .catch(funcioFalladaCallback);

    Si és tractara de funcions síncrones, podria quedar:

    try {
    let resultado = funcio1();
    let resultat2 = funcio2(resultado);
    let resultat3 = funcio2(resultat2);
    // Tratamiento de resultat3
} catch (error) {
    funcioFalladaCallback(error);
}

    Conversió de callbacks a promeses

    A pesar que moltes dels funcionalitats asíncrones ofereixen una versió que retorna promeses, existeixen Apis que continuen oferint només la seua versió mitjançant callbacks. En aquest cas, podem crear una promesa que envolte aquesta API. Per a això, crearem una promesa nova, en ús del constructor corresponent

    Un clar exemple d'això és la funció setTimeOut, que estableix un temporitzador:

    setTimeout( function() {
 console.log("Han passat 10 segons");
}, 10000);

    Aquesta funció estableix un temporitzador que dispara un event de timeout en el cap de 10000 milisegons, i en resposta a aquest event, llança la funció de callback que te especificada endins

    La idea, per a evitar problemes, és envoltar amb promeses els funcions problemàtiques al nivell més baix possible:

    const wait = function(ms) {
 return new Promise( resolve => setTimeout(resolve, ms));
 }

wait(10000).then(() => console.log("Han passat 10 segons")).catch(function(){console.log("Error")});
