    4. HTTP

    Introducció. Comunicació entre aplicacions

    Les Apis RESTFul (Representational State Transfer o Transferència d'Estat Representacional) són una arquitectura de programari orientada a recursos (ROA) per a implementar web services. Es tracta d'una arquitectura moderna i cada vegada més popular, que fa ús del protocol HTTP per a transferència de dades, i generalment el format JSON per a la seua representació. Així doncs, amb REST podrem crear aplicacions i serveis entre diversos dispositius, sempre que aquestes entenguen el protocol HTTP, sent Internet el medi natural a través del qual oferir aquests.

    Com hem dit, REST presenta una arquitectura orientada a recursos, on cada recurs del servidor disposa d'una ruta (direcció URL) diferent, coneguda també com endpoint. Aquests recursos es processen amb els mètodes de la interfície uniforme GET, POST, PUT i DELETE (HTTP té més mètodes, però no pertanyen a aquesta interfície).

    L'API que utilitzarem per als exemples es troba documentada en el següent repositori de Github. Per a accedir als recursos, podem provar amb el navegador web les adreces que en ella s'especifiquen, i que es troben allotjades al servei Railway App.

    Per exemple, pots provar des del teu navegador la següent direcció URL:

    • https://node-comarques-rest-server-production.up.railway.app/api/provincies

    Note

    Quan parlem de web services hem d'esmentar el protocol SOAP. Aquest protocol, va ser dissenyat abans que REST, i definia la forma en què diferents plataformes i llenguatges podien intercanviar dades d'una manera senzilla, fent ús de XML per a l'intercanvi d'informació.

    Més endavant i en altres mòduls aprofundirem en aquesta mena de serveis.

    Peticions HTTP

    Per a poder realitzar peticions web, ja siga a serveis REST o qualsevol altre recurs que es trobe en la web existeixen diferents llibreries que podem usar en les nostres aplicacions javascript.

    Quan treballem des de Javascript per al navegador, aquest incorpora l'objecte XMLHTTPRequest, que suposa la base sobre la qual es construeixen aplicacions AJAX (Asynchronous Javacript XML). Per part seua, Node.js incorpora de manera estándard els mòduls http i https, que ens permeten tant crear servidors HTTP/HTTPS com realitzar peticions d'aquest tipus.

    L'esquema bàsic d'una petició de tipus GET per a obtindre un recurs web seria el següent:

    const https = require('https');

https.get(URL, (res) => {
    // Variable donde guardar los datos recibidos
    let data = ''; 

    // Evento que se dispara cada vez que se reciben 
    // fragmentos de datos.
    res.on('data', (chunk) => {
        data += chunk;
    });

    // Evento que se dispara cuando se ha recibido
    // toda la respuesta.
    res.on('end', () => {
        console.log(JSON.parse(data).explanation);
    });

// Evento que se dispara en caso de error.
}).on("error", (err) => {
  console.log("Error: " + err.message);
});

    La majoria de funcionalitats del mòdul HTTP i Https són de bastant baix nivell. En aquest cas, rebem la resposta a nuestas peticions en fragments de dades que hem d'analitzar i reconstruir. Aquests fragments són bastant senzills de reconstruir quan es tracta de respostes en format JSON, però no deixa de suposar un pas addicional.

    Analitzem per parts quines hem fet:

    • En primer lloc, importem l'objecte https del mòdul amb el mateix nom:
    const https = require('https');
    • Amb aquest objecte, invoquem al seu mètode get amb el següent codi:
    https.get(URL, (res) => {
    // Cuerpo del callback    

    }).on("error", (err) => {
        console.log("Error: " + err.message);
    });

    Com veiem, al mètode GET li proporcionem la URL o recurs al qual desitgem accedir, així com una funció de callback, que rep el paràmetre resposta amb la resposta. Si es produeix alguna excepció en aquesta crida, s'executa el segon fragment de codi, mostrant l'error per pantalla.

    • Dins del cos del callback que processa les respostes, el que fem és preparar una estructura per a emmagatzemar dades quan són rebuts:
    let data = ''; 

res.on('data', (chunk) => {
    data += chunk;
});
    • I cuano acabem de llegir dades, el que fem és ja processar la resposta completa, en aquest cas, mostrar-la per pantalla:
    res.on('end', () => {
    console.log(JSON.parse(data).explanation);
 });
 ```

Vegem com aplicaríem aquest esquema per a obtindre les dades sobre províncies:

```js
import { get } from 'https';

get('https://node-comarques-rest-server-production.up.railway.app/api/comarques', res => {
    let data = '';

    // Obtenemos el código de estado de la respuesta (200=Ok)
    console.log('Status Code:', res.statusCode);
    // Y la fecha de ésta
    const headerDate = res.headers && res.headers.date ? res.headers.date : 'no response date';
    console.log('Date in Response header:', headerDate);

    res.on('data', chunk => { data += chunk; });

    res.on('end', () => { console.log(JSON.parse(data)); }
    );
}).on('error', err => {
    console.log('Error: ', err.message);
});

    Concatenant peticions

    Ara bé.. si ara volguérem per a cada província obtindre el nom de les diferents comarques, què faríem? 

    const https = require('https');

https.get('https://node-comarques-rest-server-production.up.railway.app/api/comarques', res => {
    let data = '';
    res.on('data', chunk => {
        data += chunk;
    });
    res.on('end', () => {

        let provincies = JSON.parse(data);

        for (let provincia of provincies) {
            console.log('https://node-comarques-rest-server-production.up.railway.app/api/comarques/' + provincia.provincia);
            https.get('https://node-comarques-rest-server-production.up.railway.app/api/comarques/' + provincia.provincia, res => {
                let data = '';
                res.on('data', chunk => { data += chunk; });

                res.on('end', () => {
                    let comarques = JSON.parse(data);

                    console.log(" \nComarques de " + provincia.provincia + "\n");
                    for (comarca of comarques) {
                        console.log(comarca);
                    }
                });
            }).on('error', err => {
                console.log('Error: ', err.message);
            });

        }
    });
}).on('error', err => {
    console.log('Error: ', err.message);
});

    Com veiem, quan es finalitza la recepión de les províncies, hem de recórrer aquestes, i realitzar de nou peticions, que es processen de la mateixa manera, afegint un nou nivell d'anidamiento de callbacks.

    Peticions web amb fetch

    L'API fetch es va introduir en la versió 6 d'EcmaScript, i permet realitzar peticions asíncrones mitjançant Promeses, que també es van introduir en aquesta versió. Mitjançant promeses podrem treballar amb peticions asíncrones d'una manera més còmoda que amb els callbacks.

    Aquesta funcionalitat es va implementar de manera experimental en el core de Node.js en la versió 17.5. Fins a aqueix moment, es requeria de llibreries com Axios o node-fetch.

    La manera de realitzar una petició amb fetch és relativemente senzilla, i consisteix a invocar a fetch proporcionant-li com a argument la URL del recurs que desitgem obtindre. Per exemple:

    const res = fetch('https://node-comarques-rest-server-production.up.railway.app/api/comarques');

    L'API fetch retorna un objecte de tipus Promise amb els seus dos mètodes then() i catch(). Aquests mètodes reben sengles funcions de callback que seran invocades bé quan s'obtinga resposta o bé quan es produïsca un error. Cal tindre en compte que els erros que faran que s'execute el catch són aquells relacionats amb errors de xarxa o d'un altre tipus, però no els errors HTTP que retornen un codi d'error (tipus 404, etc). Aquests errors s'hauran de tractar dins del then()

    res.then(function(result) {
    // Procesamiento de la respuesta
    })
 .catch(function(err) {
    // Tratamiento de errores de red
 });

    O usant funciones fletxa:

    res.then((result) => {
    // Procesamiento de la respuesta
    })
 .catch((err) => {
    // Tratamiento de errores de red
 });
 ```

També cal tindre en compte que el més habitual serà trobar-nos amb dues promeses encadenades per a accedir al cos del missatge que ens retorna el servidor. Vegem-lo amb un exemple. Per al cas d'obtindre les províncies, si vam mostrar el resultat per pantalla:

```js
const res = fetch('https://node-comarques-rest-server-production.up.railway.app/api/comarques/provincies');

res.then((result) => {
    console.log(result);
});

    Ens imprimirà el JSON amb tot l'objecte Response retornat pel servidor:

    Response {
  [Symbol(realm)]: null,
  [Symbol(state)]: {
    aborted: false,
    ...,
    statusText: 'OK',
    headersList: HeadersList {
      ...
    },
    urlList: [ URL {} ],
    body: { stream: undefined }
  },
  ...
    },
    [Symbol(headers map sorted)]: null
  }
}

    Est objecte de tipus Response que se'ns retorna, no disposa del contingut del cos (bodi) de manera directa, sinó que proporciona diferents mètodes per a accedir al contingut, com són .json() per a obtindre el contingut en format JSON o bé .text(), per a obtindre-ho en format text. Aquests mètode .json() i .text(), ens retornen una altra promesa, que es resoldrà quan s'haja obtingut el contingut en l'un o l'altre format. Aquesta promesa serà tractada amb un altre then encadenat, per exemple, per a mostrar el resultat:

     const res = fetch('https://node-comarques-rest-server-production.up.railway.app/api/comarques/provincies');

res.then((result) => {
    // Obtenemos el contenido en JSON
    return (result.json());
}).then((result) => {
    // Mostramos el JSON por pantalla
    console.log(result);
});

    A part de text i json, l'objecte Response proporciona altres mètodes per a l'accés al contingut. Vegem-los en la següent taula:

    Mètode Significat Exemple
    response.texto() Retorn el contingut en format text ["València","Alacant","Castelló"]
    response.json() Retorna el contingut en format JSON [ 'València', 'Alacant', 'Castelló' ]
    response.arrayBuffer() Retorna el contingut en format ArrayBuffer ArrayBuffer
    response.blob() Retorna el contingut en format Blob per a gestionar-ho amb URL.createObjectURL() data = Blob {
    [Symbol(type)]: 'application/json; charset=utf-8',
    [Symbol(buffer)]: }

    URL.createObjectURL(data)=blob:null/d7cf5197-0254-4feb-bdbe-cf9aaf1863ac
    response.formData() Retorna el contingut en format FormData

    async/await

    En l'apartat anterior ja vam introduir la millora sintàctica async/await d'EcmaScript 2017. Aquesta mateixa sintaxi podem utilitzar-la per a processar les promeses que rebem quan usem l'API Fetch

    L'exemple d'obtenció de les províncies seria:

    async function obtrenirProvincies() {
    let resposta = await fetch('https://node-comarques-rest-server-production.up.railway.app/api/comarques/provincies');
    let respostaJSon = await resposta.json();
    console.log(respostaJSon);
}

obtrenirProvincies();
